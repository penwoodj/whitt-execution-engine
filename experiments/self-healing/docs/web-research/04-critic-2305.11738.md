# Source: CRITIC — LLMs Can Self-Correct with Tool-Interactive Critiquing

- **URL:** https://arxiv.org/abs/2305.11738
- **Retrieved:** 2026-08-24 (abstract + websearch)

## Method Mechanics

```
output = generate(task)
for n in 1..N:
    critique = tool_verify(output)    # external tool: search, calculator, interpreter
    if critique clean: break
    output = correct(output, critique)
```

- **N:** typically 3 iterations
- Key: verification via EXTERNAL tools, not self-judgment. Critique grounded in tool output.

## Healing Trigger

Tool verification mismatch (fact check fail, code exec fail, toxicity classifier hit).

## Metrics

F1 +7.7 on QA tasks; toxicity −79.2%. Correction gains vanish without tool grounding.

## What We Borrow

1. **External verification beats self-judgment** — justifies our deterministic detector suite (detect.py = "tool" verifier) over LLM self-critique, especially for 4B–9B local models
2. **F2 tool re-selection lineage** — when tool call fails (CRITIC exec fail), swap tool rather than re-prompt — direct ancestor of primary paper F2 strategy
3. **n=3 verify-correct rounds** — consistent iteration cap

## Divergence

CRITIC verifies content w/ real tools (search etc). Our spoof phase verifies structure + injected signals via python. Live phase could wire real exec checks (code cases) later.
