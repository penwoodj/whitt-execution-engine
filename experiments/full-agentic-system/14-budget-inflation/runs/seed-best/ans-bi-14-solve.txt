### Phase 1 RULE SCAN

The following rules govern the state changes during the event sequence. Each rule is listed on one line with its trigger condition.

1.  **Initial Limit Rule**: Steps 1–5 allow an error rate up to 2.0%; steps 6–10 allow up to 1.0%. Trigger: Arrival of observation at specific step index.
2.  **Breach Detection Rule**: If observed error > limit, the state transitions to a breach condition. Trigger: Comparison result of Observation vs Limit.
3.  **First Breach Action (Rollback)**: Upon first breach, rollback exactly one step (decrement current step count), mark the breached observation as SPENT, and tighten limits for all *remaining* steps to 0.8%. Trigger: First occurrence of a breach event.
4.  **Second Breach Action (Stop)**: Upon second breach, halt the rollout immediately, set status to STOPPED, freeze `rollout_pct` at current step value × 10, and set `stages_done` to observations consumed so far. Trigger: Second occurrence of a breach event.
5.  **Completion Rule**: If no breaches occur after all steps (1–10) are processed, set status to DONE, `rollout_pct` = 10 × 10, and `stages_done` = 10. Trigger: End of sequence with zero breach count.
