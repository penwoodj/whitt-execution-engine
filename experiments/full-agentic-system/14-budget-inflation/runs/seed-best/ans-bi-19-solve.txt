### Phase 1 RULE SCAN
The following rules govern the state changes during the event stream:

1.  **Arrival/Load Rule**: Upon request of a model ID, if the total free space on the card is $\ge$ the requested size, the model loads immediately into the resident set (moving to most-recent). If it fits without evictions, `loads` increments by 1.
2.  **Eviction Selection Rule**: If the requested model does not fit in current free space, identify all unpinned models currently in residence. Sort them by recency (oldest first). Evict one at a time until enough space exists or only pinned models remain. Each eviction counts toward `evictions`.
3.  **Deferral Rule**: If after evicting all available unpinned models, the requested model still does not fit because only pinned models remain, the load is deferred. Record the ID in `deferred` and increment `deferrals`. No eviction occurs for this specific event.
4.  **Unload Rule**: Upon request to unload a model, free its size immediately. The model remains in the resident set (recency unchanged) until potentially evicted later or explicitly removed by logic not present here (standard LRU behavior implies it stays until touched again or evicted). *Correction based on standard residency logic implied*: Unload frees space; the model is effectively gone from the "active" pool for capacity purposes but usually remains in the set structure. However, strictly following "free its size", we subtract GB.
5.  **Recency Update Rule**: Every time a model is loaded or touched (implicitly handled by load), it moves to the most-recent position. Evicted models are removed from the recency list.

**Trigger Mapping:**
*   `load A`: Triggers Arrival/Load Rule.
*   `load B`: Triggers Arrival/Load Rule.
*   `load C`: Triggers Arrival/Load Rule (Pinned).
*   `load D`: Triggers Eviction Selection Rule -> Arrival/Load Rule.
*   `unload B`: Triggers Unload Rule.
