### Phase 1: RULE SCAN
*List of rules changing state during the event sequence:*

1. **Load Request Rule**: Triggered by `load A`. Adds model 'A' (8GB resident size) to memory if capacity allows; otherwise triggers eviction logic.
2. **Pinned Model Exclusion Rule**: Triggered implicitly by all load/eviction steps. Prevents evictions of pinned models ('C') regardless of LRU status or capacity pressure.
3. **Capacity Check & Eviction Selection Rule**: Triggered by `load D` (which fails immediately). Checks free space; selects least-recently-touched (LRU) *unpinned* model for eviction to make room.
4. **Eviction Execution Rule**: Triggered by the capacity check in step 3. Removes selected unpinned model(s) from memory, freeing their resident size (A1=1GB, B2=2GB). Note: Model sizes are A=1, B=2, C=3, D=4 GB.
5. **Deferred Load Rule**: Triggered by `load D` after evictions still fail to fit the load. Since only pinned model 'C' remains and it cannot be evicted, the load is deferred (not added yet).
6. **Unload Request Rule**: Triggered by `unload D`. Removes model 'D' from memory if present; no eviction logic required as this is a voluntary removal.
