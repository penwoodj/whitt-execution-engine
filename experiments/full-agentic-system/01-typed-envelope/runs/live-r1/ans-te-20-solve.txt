Phase 1 RULE SCAN: List of rules changing state during tonight's events, triggered by specific claims/events:

1. **Retry Backoff Rule**: Triggers on every failed attempt; sets wait time $W_{n+1} = W_n \times 2$ starting at base $3s$.
2. **Attempt Cost Rule**: Consumes budget of $3$ tokens per failed or successful attempt execution.
3. **Wait Cost Rule**: Consumes budget of $1$ token per second of wait time observed before an attempt runs.
4. **Budget Check Rule (Pre-Execution)**: Checks if $(Cost_{attempt} + Cost_{wait}) > Budget$. If true, triggers suppression flow.
5. **Suppression Double-Budget Rule**: Upon triggering the budget check fail, doubles the available budget exactly once and re-evaluates the same cost against the new limit.
6. **Event Execution Rule**: Advances state only after a successful attempt (the 4th one in this sequence).
7. **Final State Aggregation Rule**: Computes total attempts ($N$), total seconds waited, final remaining budget, and boolean suppression status based on the walked ledger.
