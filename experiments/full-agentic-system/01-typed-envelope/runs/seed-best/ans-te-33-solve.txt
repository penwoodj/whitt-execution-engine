### Phase 1 RULE SCAN
*Listing every rule that changes state during the event sequence, including triggers.*

1. **Arrival Rule**: `HIGH` arrives at minute 2; triggers preemption of any running LOW job and blocks all other jobs until completion.
2. **Preemption Loss Rule**: Upon preemption by `HIGH`, work past the last checkpoint (every 2 minutes) is wasted; triggers state change to "wasted" for the preempted job.
3. **Resume Priority Rule**: A resumed LOW job outranks a fresh LOW job at any tie in start minute; determines scheduling order when core becomes free.
4. **Start Minute Ordering Rule**: LOW jobs take the core in order of their start minutes (0 before 1); determines initial scheduling if no preemption occurs.
5. **Waiting Queue Rule**: A LOW whose start minute arrives while the core is busy simply waits; triggers state change to "waiting" until core frees.
6. **Completion Order Rule**: Completion order is determined by finish time, with ties broken by resume status (resumed before fresh) or start minute if applicable.
7. **Makespan Calculation Rule**: Makespan counts from the first start of any job to the last finish; triggers final state aggregation.
