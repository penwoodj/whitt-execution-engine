### Phase 1 RULE SCAN
Based on the task description and the "whole law" provided for tonight's rotation:

1.  **Arrival Order Rule**: Events must be processed strictly in the order they appear in the requested stream (`load A`, `load C`, `load D`, `unload D`). No reordering or batching is allowed.
2.  **Fit Check Rule**: Before processing a load, check if the requested size fits within the current free space on the card (8GB total).
3.  **Eviction Selection Rule**: If a load does not fit, evict models one-by-one starting with the **Least-Recently-Touched (LRT)** model that is **Unpinned**. Pinned models are never selected for eviction.
4.  **Recency Update Rule**: Upon any successful load or touch of a resident model, update its position to Most-Recently-Touched (MRT).
5.  **Deferral Rule**: If a load does not fit and all remaining resident models are Pinned (and thus cannot be evicted), the request is deferred. No eviction occurs; no space is freed. The ID of the requested model is recorded as deferred.
6.  **Unload Rule**: An unload frees the specified size immediately if the model is resident. If the model is not resident, it is a no-op (state unchanged).
7.  **Counting Rules**: `loads` increments only on successful fits. `evictions` increments for every single model evicted during an event. `deferrals` increments only when a request is turned away due to lack of space and inability to evict pinned models. `deferred` holds the list of IDs that were deferred in arrival order.

**Trigger Mapping:**
*   **Event 1 (`load A`)**: Triggers Fit Check -> Load (No eviction needed).
*   **Event 2 (`load C`)**: Triggers Fit Check -> Eviction Selection (Evict LRT Unpinned) -> Load.
*   **Event 3 (`load D`)**: Triggers Fit Check -> Eviction Selection (Evict LRT Unpinned) -> Load.
*   **Event 4 (`unload D`)**: Triggers Unload Rule -> Free Space Update.
