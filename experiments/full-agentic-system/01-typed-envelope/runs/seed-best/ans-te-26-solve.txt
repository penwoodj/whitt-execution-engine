### Phase 1 RULE SCAN

Based on the task description and the "whole law for tonight", here are the rules that change state during the event stream:

1.  **Load Rule**: A request to load a model triggers an attempt to place it in resident memory. If space exists, the model is loaded (state changes: `loads` increments).
2.  **Eviction Rule**: If a load cannot fit, the system evicts the least-recently-touched (LRT) *unpinned* models one at a time until enough space exists for the requested model. Each eviction increments the `evictions` counter and removes the model from resident memory.
3.  **Deferral Rule**: If a load cannot fit even after evicting all available unpinned models (because only pinned models remain), the request is deferred. The model ID is added to the `deferred` list, and no eviction occurs for this specific event (`evictions` does not increment).
4.  **Recency Rule**: Every time a model is loaded or touched (implicitly by being resident), it moves to the most-recent position in the recency list. The LRT model is determined by scanning from oldest to newest.
5.  **Pinned Constraint**: Pinned models (C, N) are never evicted regardless of their age or space pressure. They remain resident until explicitly unloaded or if the system defers a load due to lack of unpinned space.
6.  **Unload Rule**: A request to unload a model frees its size from memory immediately. If the model is not resident, this is a no-op (state change: `free` increases).

**Trigger Mapping:**
*   Event "load A": Triggers Load Rule.
*   Event "load B": Triggers Load Rule -> Eviction Rule (if needed) -> Recency Rule.
*   Event "load C": Triggers Load Rule.
*   Event "load D": Triggers Load Rule -> Eviction Rule (if needed).
*   Event "unload B": Triggers Unload Rule.
