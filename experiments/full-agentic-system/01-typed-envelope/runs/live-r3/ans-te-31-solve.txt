### Phase 1 RULE SCAN
The following rules govern state changes during the event sequence:

1. **Arrival Rule**: `HIGH` arrives at $t=3$; transitions Core from `Idle/LOW-running` to `Busy(HIGH)`.
2. **Preemption Rule (Start)**: Upon `HIGH` arrival, if a LOW job is running, execution halts immediately; work since last checkpoint becomes wasted.
3. **Completion Rule**: A job finishes when its remaining duration reaches 0 while Core is free.
4. **Resume Rule**: When `HIGH` departs ($t=5$), the system selects the next eligible LOW job based on: (a) Start Time priority, (b) Resumed vs Fresh tie-breaker, (c) FIFO for same start/resume status.
5. **Checkpoint Logic**: LOW jobs checkpoint every 2 minutes of *running time*; preemption invalidates work post-checkpoint.
6. **Wasted Calculation Rule**: `wasted_min` = sum of durations between last checkpoint and preemption point for any preempted job.
7. **Makespan Definition**: Time from first start ($t=0$) to final completion of all LOW jobs.

**Triggers:**
- Event $E_1$ (Start LOW1): Triggers Rule 3 (Initial Start).
- Event $E_2$ (Checkpoint LOW1 @ t=2): Triggers Rule 5 (Checkpointing).
- Event $E_3$ (Arrival HIGH @ t=3): Triggers Rule 2 (Preemption) and Rule 6 (Wasted Initiation).
- Event $E_4$ (Finish HIGH @ t=5): Triggers Rule 4 (Resume Selection).
- Event $E_5$ (Completion LOW1 @ t=8): Triggers Rule 3 (Finalization).
- Event $E_6$ (Start/Completion LOW2 @ t=8->t=10): Triggers Rule 3 & 7.
