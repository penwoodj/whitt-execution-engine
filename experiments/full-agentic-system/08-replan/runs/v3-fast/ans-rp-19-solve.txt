### Phase 1 RULE SCAN

The following rules govern the state changes during the event stream:

1.  **Arrival/Load Rule**: Upon request of a model $M$ with size $S_M$, if current free space $\ge S_M$, load $M$. If successful, increment `loads`.
2.  **Eviction Selection Rule**: If current free space $< S_M$, identify the set of unpinned resident models. Sort them by recency (Least Recently Touched first).
3.  **Eviction Execution Rule**: Evict unpinned models one at a time in sorted order, subtracting their sizes from the required load size until either:
    *   The remaining required size fits in current free space (increment `evictions` by count of evicted models), OR
    *   No unpinned models remain.
4.  **Deferral Rule**: If after exhausting all unpinned models, the required model still does not fit (i.e., only pinned models remain and total capacity is insufficient), defer the load. Record the request ID in `deferred` list, increment `deferrals`. Do not increment `evictions`.
5.  **Recency Update Rule**: Upon any successful load or eviction of a specific model instance, that model becomes Most Recently Touched (MRT).
6.  **Unload Rule**: Upon request to unload model $M$, if $M$ is resident, subtract its size from free space and remove it from residents. If $M$ is not resident, this is a no-op.

**Trigger Mapping:**
*   Event `load A` triggers Rules 1 & 5.
*   Event `load B` triggers Rules 1 & 5.
*   Event `load C` triggers Rules 1 & 5.
*   Event `load D` triggers Rules 2, 3, and potentially 4 or 5 depending on fit.
*   Event `unload B` triggers Rule 6.
