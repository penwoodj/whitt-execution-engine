### Phase 1 RULE SCAN
The following rules govern state changes during the event sequence. Each line lists the rule and its trigger condition.

1. **Arrival Rule**: Triggered by every request arriving in strict order; checks pool availability against the ask amount.
2. **Grant/Partial/Deny Rule**: If `pool >= ask`, grant full (`pool -= ask`); if `0 < pool < ask`, grant partial (`pool = 0`); if `pool == 0`, deny (add ID to denied list).
3. **Expiry Trigger Rule**: Triggered immediately after a request completes; identifies the specific grant associated with that request for expiry processing.
4. **Return Calculation Rule**: Calculates return as `floor(granted_amount / 2)` based strictly on the amount actually granted in step 2, not the ask.
5. **Pool Refill Rule**: Adds the calculated return to the pool immediately before the next event is processed (return lands right before the trigger request's successor).
