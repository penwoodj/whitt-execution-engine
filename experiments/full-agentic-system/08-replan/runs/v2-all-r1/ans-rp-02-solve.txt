### Phase 1 RULE SCAN
*Listing every rule that changes state during the event or claim list.*

1.  **Grant Rule**: A request arriving at a non-zero pool is granted up to `min(ask, current_pool)`. State change: Pool decreases by grant amount; Request status becomes "Granted".
2.  **Denial Rule**: A request arriving when the pool is exactly zero is denied (status "Denied"). State change: Request listed in denial log; Pool remains zero.
3.  **Expiry Trigger Rule**: Upon completion of a specific request ID named in an expiry sentence, that specific grant expires. State change: Prepares return logic for the next step.
4.  **Return Calculation Rule**: The expired grant returns `floor(granted_amount / 2)` tokens to the pool. State change: Pool increases by returned amount; Grant count decreases.
5.  **Timing Rule (Precedence)**: The expiry return lands *before* the arrival of the request named in the trigger, but strictly *after* the completion of the triggering request.
