### Phase 1 RULE SCAN
*Listing every rule that changes state during the event or claim list.*

1.  **Grant Rule**: A request arriving at a non-zero pool is granted `min(ask, current_pool)`. State change: Pool decreases by grant amount; Request status becomes "Granted".
2.  **Denial Rule**: A request arriving when the pool is exactly zero is denied (listed by ID). State change: Request status becomes "Denied"; Pool remains zero.
3.  **Expiry Trigger Rule**: Upon completion of a specific request (the trigger), any grant associated with that request expires. State change: The system prepares to return tokens based on the expired grant's history.
4.  **Return Calculation Rule**: An expired grant returns `floor(granted_amount / 2)` tokens. State change: Pool increases by returned amount; Grant record is cleared.
5.  **Timing Rule (Precedence)**: The expiry return happens *before* the next request in arrival order is processed, but strictly after the trigger request completes.
