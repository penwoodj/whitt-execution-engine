1. **Arrival Rule**: Requests arrive in strict order; each asks for a fixed number of tokens from the current pool balance.
2. **Grant/Partial/Deny Rule**: If `ask <= pool`, grant full amount (`pool -= ask`). If `ask > pool` but `pool > 0`, grant partial amount (`pool = 0`). If `pool == 0`, deny request (add ID to denied list).
3. **Expiry Trigger Rule**: Upon completion of a specific request (the trigger), any associated expired grant returns immediately before the next event is processed.
4. **Return Calculation Rule**: The return amount is exactly half (`floor(granted_amount / 2)`) of what was actually granted to that specific trigger, rounded down.
5. **State Update Rule**: Pool balance updates sequentially: `new_pool = old_pool - grant + return` (where return happens immediately after the triggering event).
