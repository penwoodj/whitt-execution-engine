### Phase 1 RULE SCAN (First Half Only)
*Rules governing the release-token pool for tonight's deploy window.*

1. **Grant Rule**: Requests arrive in strict order; if the pool has tokens, grant `min(ask, pool)` and subtract from pool. A request is "granted" even if partial; it is only "denied" if the pool is exactly zero upon arrival.
2. **Expiry Rule**: The grant for `r1` expires after `r2` completes. Upon expiry, return `floor(granted_amount / 2)` to the pool. This rule binds specifically to the grant received by `r1`.

### Phase 2 LEDGER WALK (First Half Only)
*Applying events in strict arrival order.*

**Initial State**: Pool = 50.

1. **Event r1 arrives (Ask: 4)**
   - Rule: Grant Rule applies.
   - Calculation: `grant = min(4, 50) = 4`.
   - State Update: Pool becomes `50 - 4 = 46`.

   - Calculation: `grant = min(6, 46) = 6`.

   - *Trigger for Expiry*: The grant from r1 expires now (after r2 completes).
   - Rule: Expiry Rule applies to r1's grant.
   - Calculation: `return = floor(4 / 2) = 2`.
   - State Update: Pool becomes `40 + 2 = 42`.

3. **Event r3 arrives (Ask: 9)**
