### Phase 1 Rule Scan (First Half Only)
Based on the text describing the "release-token pool" and its specific rules for tonight's deploy window:

1.  **Grant Rule**: A request arriving at a non-empty pool is granted up to `min(pool_size, ask_amount)`. The pool decreases by this grant amount.
2.  **Denial Rule**: A request arriving when the pool size is exactly zero is denied and listed by ID. (Note: Text clarifies that if the pool has tokens, even fewer than the ask, it grants; denial only happens at exact zero).
3.  **Expiry Rule**: The grant for `r1` expires after `r2` completes. Upon expiry, it returns `floor(granted_amount / 2)` to the pool.
4.  **Return Timing Rule**: The return from an expired grant lands immediately before the request that triggered the expiry (conceptually), but logically applies to the state *after* the triggering event (`r2`) and *before* any subsequent events (`r3`).
