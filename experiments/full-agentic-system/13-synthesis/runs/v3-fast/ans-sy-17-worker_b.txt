### Phase 1: Rule Scan (Part B - Residency)

**Rules Identified for Part B:**
1.  **Capacity & Eviction Policy:**
    *   Models A, C, D have resident sizes of 2GB, 4GB, and 3GB respectively.
    *   Model B is pinned (never evicted).
    *   Evictions target the Least-Recently-Touched (LRT) unpinned model.
    *   Load cost: 30s; Unload cost: 10s.
2.  **Deferred Load Logic:**
    *   A load that cannot fit after exhausting all LRT unpinned models is deferred if pinned models remain and still don't fit (or simply if no space exists).
    *   The `deferred` ID corresponds to the specific load command that failed to execute due to lack of capacity.
3.  **Counting Logic:**
    *   `loads`: Counts every load command actually executed in the stream.
    *   `evictions`: Counts every eviction actually performed during the stream (even if a subsequent load is deferred).
    *   `deferrals`: Implicitly 0 or 1 based on whether a load was successfully skipped/deferred. The output format asks for an array of IDs, so we track the specific ID that failed.

**Event Stream:**
1.  Load A (2 GB)
2.  Load C (4 GB)
3.  Load D (3 GB)
4.  Unload D (3 GB)
