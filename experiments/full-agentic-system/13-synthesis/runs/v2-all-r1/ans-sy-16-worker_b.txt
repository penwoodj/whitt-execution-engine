### Phase 1: Rule Scan (Part B - Residency)

**Rules Identified for Part B:**
1.  **Capacity & Eviction Policy**: One 8GB card tonight; Models A-D resident sizes (A=1, B=2, C=3, D=4 GB); Model C is pinned and never evicted.
2.  **Eviction Selection**: Evictions choose the least-recently-touched (LRU) unpinned model.
3.  **Timing Costs**: Loads cost 30s; Unloads cost 10s.
4.  **Load Execution Logic**: A load that cannot fit evicts as many LRU unpinned models as needed. If only pinned models remain and it still does not fit, the load defers.
5.  **Deferred Load Definition**: A load is deferred after evicting every unpinned resident *and* room is still insufficient. The deferred id is that load's own id.
6.  **No-Op Unload**: An unload for a model no longer resident is a no-op (does not count towards loads/evictions).
7.  **Count Definitions**: Loads counts every executed load command. Evictions counts every actual eviction performed (even if the load ends up deferred). Deferrals only happen when a load truly cannot fit after max evictions.
