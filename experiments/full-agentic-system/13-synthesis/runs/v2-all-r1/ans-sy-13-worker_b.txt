### Phase 1: Rule Scan (Part B - Residency)

**Rules Identified for Part B:**
1.  **Initial State Definition**: One 8GB card resident with models A(1), B(4), C(2), D(6). Model B is pinned and never evicted.
    *   *Trigger*: System initialization (implicit before first event).
2.  **Eviction Policy**: Evict Least-Recently-Touched (LRT) unpinned model if load cannot fit.
    *   *Trigger*: Load command execution when capacity is insufficient.
3.  **Load Execution & Costing**: Loads cost 30s, Unloads cost 10s. "Loads" count includes every executed load command.
    *   *Trigger*: Successful or deferred load commands.
4.  **Deferred Load Logic**: If a load cannot fit even after evicting all unpinned models (and pinned remain), the load is deferred. The `deferred` list contains the ID of this specific load. Evictions performed to attempt the fit still count towards the total eviction metric.
    *   *Trigger*: Load command where remaining capacity < requested size AND no unpinned space exists to free up more.
5.  **No-Op Handling**: Unloading a non-resident model is a no-op (no cost, no state change).
    *   *Trigger*: `unload B` event when B is not resident.
