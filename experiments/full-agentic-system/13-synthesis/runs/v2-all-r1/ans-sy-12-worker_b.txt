### Phase 1: Rule Scan (Part B - Residency)

**Rules Identified for Part B:**
1.  **Capacity & Pinning Rule**: Model C is pinned and never evicted. Evictions target the least-recently-touched (LRT) unpinned model.
2.  **Load Execution Logic**: A load command executes if there is room. If a load cannot fit, it triggers evictions of LRT unpinned models until it fits or only pinned models remain.
3.  **Deferred Load Rule**: If after exhausting all unpinned residents (evicting them), the requested model still does not fit into the remaining space (which would be just Model C's size if others are gone, but practically implies no room for a large model if C is the only one left and it doesn't match), the load is deferred. The `deferred` ID is that specific load command.
4.  **Cost Counting Rule**: `loads` counts every executed load command in the stream (including those that triggered evictions).
5.  **Eviction Counting Rule**: `evictions` counts every actual eviction performed, even if the subsequent load ends up deferred.
6.  **No-Op Unload Rule**: An unload for a model no longer resident is ignored (no-op).
