### Phase 1 RULE SCAN
*List of rules that change state during the event or claim list:*

1.  **Arrival/Ask Rule**: A request arrives asking for a fixed number of tokens; if the pool has enough, it grants the full amount and subtracts from the pool.
2.  **Partial Grant Rule**: If the pool cannot cover the full ask, it grants whatever remains in the pool (partial grant) and drains the pool to zero.
3.  **Denial Rule**: A request arriving at an empty pool is denied (granted amount = 0), listed by ID, and the state does not change further for that event.
4.  **Expiry Trigger Rule**: The grant for `r1` expires after request `r2` completes; this rule activates specifically when `r2` finishes processing.
5.  **Return Calculation Rule**: Upon expiry, half of the *granted* tokens (not asked) are returned to the pool, rounded down.
6.  **Timing Constraint Rule**: The return arrives right before the request the trigger names (`r3`), not after it.
