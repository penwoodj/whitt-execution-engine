### Phase 1 RULE SCAN
*Listing every rule that changes state during the event or claim list.*

1.  **Grant Rule**: A request arriving at a non-zero pool is granted `min(ask, current_pool)`, reducing the pool by that amount; if `current_pool` becomes zero after this grant, the next request will be denied.
2.  **Denial Rule**: A request arriving when the pool is exactly zero is denied (listed by ID); a request arriving at a non-zero pool is never denied, even if the ask exceeds the remaining balance.
3.  **Expiry Trigger Rule**: Upon completion of request `rN`, any grant associated with `r(N-1)` that has expired returns tokens to the pool immediately before processing `rN`.
4.  **Return Amount Rule**: The expiry return equals `floor(granted_amount_of_expired_grant / 2)`.
5.  **Expiry Target Rule**: Only the specific grant named by the trigger request ID (the one completing) causes a return; no other grants return.
