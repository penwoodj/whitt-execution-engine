### Phase 1 RULE SCAN
*Listing every rule that changes state during the event or claim list.*

1.  **Grant Rule**: A request arriving at a non-zero pool is granted `min(ask, current_pool)`, reducing the pool by that amount; if the ask exceeds the remaining pool, the grant is partial but still counts as "granted" (never denied).
2.  **Denial Rule**: A request arriving when the pool is exactly zero is denied and listed by ID; this state change adds an ID to the `denied` list.
3.  **Expiry Trigger Rule**: Upon completion of a specific request (the trigger), any grant associated with that trigger expires if it was granted previously.
4.  **Return Calculation Rule**: The expired grant returns `floor(granted_amount / 2)` tokens to the pool immediately before the next event is processed.
5.  **Pool State Update Rule**: After every action (grant, return), the pool balance updates strictly: `new_pool = old_pool - granted + returned`.
