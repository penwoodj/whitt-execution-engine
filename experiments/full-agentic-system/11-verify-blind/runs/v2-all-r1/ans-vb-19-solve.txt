### Phase 1 RULE SCAN

The following rules govern the state changes during the event stream:

1.  **Arrival Rule**: Each request (load/unload) arrives in strict order and triggers a check against current capacity.
2.  **Fit Check Rule**: If the requested size fits within `Total Capacity - Sum(Resident Sizes)`, the model loads immediately without eviction.
3.  **Eviction Selection Rule**: If the request does not fit, identify all unpinned models sorted by recency (Least Recently Touched first).
4.  **Single Eviction Step Rule**: Evict exactly one LRU unpinned model per step until either:
    *   The request fits (`Free + Evicted Size >= Requested Size`).
    *   No unpinned models remain.
5.  **Deferred Load Rule**: If no unpinned models remain and the request still does not fit, the load is deferred (no eviction occurs for this step). Record the ID as a deferral.
6.  **Recency Update Rule**: Upon any successful load or eviction of an existing resident, that model's recency is updated to "Most Recently Touched".
7.  **Unload Rule**: If the target model exists and is pinned, it remains (no-op). If it exists and is unpinned, its size is freed and it is removed from residents. If it does not exist, it is a no-op.
8.  **Counter Accumulation Rule**: Increment `loads` only on successful loads. Increment `evictions` for every model physically evicted (even if the load later defers). Increment `deferrals` and record ID only when a load fails after exhausting unpinned residents.
