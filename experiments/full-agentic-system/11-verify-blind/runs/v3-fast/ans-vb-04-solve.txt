### Phase 1 RULE SCAN
*Listing every rule that changes state during the event or claim list.*

1.  **Arrival Rule**: A request arrives in strict arrival order; if the pool has tokens ($>0$), it is processed (granted fully or partially); if the pool is empty ($=0$), it is denied and listed by ID.
2.  **Grant/Partial Rule**: If a request asks for $X$ and the pool holds $Y$, where $Y > 0$:
    *   If $Y \ge X$: Grant $X$, Pool becomes $Y - X$.
    *   If $Y < X$: Grant $Y$ (partial), Pool becomes $0$. The request is still considered "granted" and never denied.
3.  **Denial Rule**: A request arriving when the pool is exactly $0$ is denied, listed by ID, and remains denied permanently.
4.  **Expiry Trigger Rule**: Upon completion of a specific request (the one named in the expiry sentence), any associated expired grant returns immediately.
5.  **Return Amount Rule**: The return amount is calculated as $\lfloor \text{GrantedAmount} / 2 \rfloor$ (half rounded down).
6.  **Timing Rule**: The return lands *before* the next request is processed, but strictly *after* the trigger request completes.
