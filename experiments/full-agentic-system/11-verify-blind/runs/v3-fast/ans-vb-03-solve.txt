### Phase 1 RULE SCAN
*Listing every rule that changes state during the event or claim list.*

1.  **Grant Rule**: A request arriving at a non-zero pool is granted `min(ask, current_pool)`, reducing the pool by that amount; if the ask exceeds the remaining pool, it is still a "granted" (partial) request, not denied.
2.  **Denial Rule**: A request arriving when the pool is exactly zero is denied and listed by ID; this state change adds an ID to the `denied` list.
3.  **Expiry Trigger Rule**: Upon completion of a specific request (the trigger), any grant associated with that request expires.
4.  **Return Calculation Rule**: The expired grant returns `floor(granted_amount / 2)` tokens to the pool immediately before the next event is processed.
5.  **Pool State Update Rule**: The pool balance updates sequentially: first by subtraction (grant/deny), then by addition (return), resulting in a new state for the subsequent event.
