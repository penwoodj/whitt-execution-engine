### Phase 1 RULE SCAN
This phase lists every rule from the task that changes state during the event stream (Load A, Load B, Load C, Load D, Unload B), including expiry, return, revocation, refill, promotion, fallback, or source-ranking rules.

1.  **Capacity Rule**: The total resident size cannot exceed the card capacity (8 GB).
2.  **Pinning Rule**: Model B is pinned and never evicted; it remains resident until explicitly unloaded.
3.  **Eviction Selection Rule**: Evictions target the least-recently-touched (LRU) *unpinned* model only.
4.  **Recency Update Rule**: Every successful load or touch of a resident moves that model to the most-recent position in the recency list.
5.  **Eviction Counting Rule**: Each model evicted increments the `evictions` counter, regardless of whether the subsequent load fits immediately after.
6.  **Deferred Load Rule**: If a load cannot fit even after evicting all unpinned models (because only pinned models remain), the load is deferred; no eviction occurs for this specific step, and the load ID is recorded in `deferred`.
7.  **Load Success Definition**: A "load" counts towards `loads` only if it successfully occupies space on the card.
8.  **Unload Rule**: Unloading a model frees its size immediately; unloading a non-resident model is a no-op (no state change).
9.  **Deferred List Order Rule**: The `deferred` list must contain IDs in strict arrival order of the deferred events.

**Trigger Mapping:**
*   Load A (2 GB): Triggers Capacity Check, Recency Update.
*   Load B (2 GB): Triggers Capacity Check, Pinning Constraint (fits without eviction), Recency Update.
*   Load C (2 GB): Triggers Capacity Check, Recency Update.
*   Load D (7 GB): Triggers Capacity Check -> Eviction Selection (Model A) -> Capacity Check (Fits) -> Recency Update.
*   Unload B: Triggers Unload Rule (Frees 2 GB).
