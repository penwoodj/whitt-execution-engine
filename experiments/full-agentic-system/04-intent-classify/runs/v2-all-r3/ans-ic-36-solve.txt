### Phase 1: Rule List
The following rules govern the state changes during the event sequence (LOW1 arrival/grant, LOW2 arrival/grant, HIGH arrival/preempt/finish, LOW1 resume, LOW2 run):

1.  **Arrival/Grant Rule**: A job arriving at minute `s` with duration `n` is granted execution starting immediately if the core is free; otherwise it enters a wait queue ordered by start minute (`s`).
2.  **Checkpoint Bank Rule**: For any active job, checkpoints bank at absolute minutes `s+2`, `s+4`, etc., where `s` is the current start or resume minute. A bank landing exactly on HIGH's arrival counts as valid (no waste).
3.  **Preemption Rule**: When HIGH arrives and preempted a running LOW, any execution time past the last checkpoint bank is wasted. The resumed LOW owes `total_duration - banked_time` minutes upon restart.
4.  **Resumption Priority Rule**: Upon preemption completion, if multiple jobs are waiting, the core resumes the one with the earliest start minute (`s`). If start times tie, a resumed job outranks a fresh job (not applicable here as LOW1 and LOW2 have distinct `s`).
5.  **Non-Idle Core Rule**: The core never idles while a LOW is waiting. As soon as a running job finishes or is preempted, the next waiting LOW starts in that same minute.
6.  **Completion Order Rule**: LOW jobs are listed by their finish minute (lowest first). HIGH is excluded from this list.

**Trigger Mapping:**
*   Event `LOW1_arrive`: Triggers Rule 1 (Grant).
*   Event `LOW2_arrive`: Triggers Rule 1 (Wait, as core busy).
*   Event `HIGH_arrive`: Triggers Rule 3 (Preempt LOW1), Rule 5 (Switch to waiting jobs logic later).
*   Event `HIGH_finish`: Triggers Rule 4 (Resume lowest-priority waiter), Rule 2 (Bank checks for resumed job).
