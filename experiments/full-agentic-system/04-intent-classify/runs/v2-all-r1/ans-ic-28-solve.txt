### Phase 1 RULE SCAN

The following rules govern the state changes during the event stream:

1.  **Load Rule**: A load request attempts to occupy `size` GB of free space. If sufficient free space exists (including pinned models), the model is loaded, resident set updated with new recency, and `loads` count increments.
2.  **Eviction Rule**: If a load cannot fit because total capacity < requested size + current usage, the system evicts the Least-Recently-Touched (LRT) *unpinned* models one by one until enough space is freed or only pinned models remain. Each eviction increments the `evictions` count and removes the model from the resident set.
3.  **Deferral Rule**: If a load cannot fit even after evicting all unpinned models (i.e., only pinned models remain), the request is deferred. The model ID is added to the `deferred` list, `deferrals` count increments, and no eviction occurs for this specific event.
4.  **Recency Rule**: Every time a model is loaded or touched (implicitly by being resident during an eviction check? No, only on load/unload/eviction), its position in the recency list updates to "most recent". The LRT model is at the start of the list.
5.  **Unload Rule**: An unload request frees `size` GB immediately if the model is resident. If not resident (already evicted or never loaded), it is a no-op. Free space increases, and recency updates for remaining models.
6.  **Pinned Constraint**: Pinned models are never candidates for eviction. They remain in the resident set regardless of pressure.
