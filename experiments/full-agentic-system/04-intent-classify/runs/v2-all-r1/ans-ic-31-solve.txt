### Phase 1: RULE SCAN
The following rules govern the state changes during the event sequence (arrivals, grants, preemptions, resumptions):

1.  **Arrival Rule**: `HIGH` arrives at minute 3; triggers immediate preemption of any running `LOW` job and halts all other execution until `HIGH` completes.
2.  **Grant/Start Rule**: `LOW` jobs start or resume in order of their absolute start minutes (`s`). A resumed job outranks a fresh job if they share the same start minute tie-breaker (not applicable here as starts differ).
3.  **Checkpoint Bank Rule**: Checkpoints bank at `start_or_resume + 2` and every subsequent `+ 2` running minutes, tracked in absolute time. Banks landing exactly on the preemption trigger count; work past the last bank is wasted.
4.  **Preemption Waste Rule**: On preemption by `HIGH`, execution stops immediately. Minutes run between the last checkpoint bank and the preemption event are marked as "wasted" and must be redone upon resume.
5.  **Resume Priority Rule**: Upon resumption, the core picks the waiting job with the earliest start minute (`s`). If multiple jobs have the same `s`, the one that was already running (resumed) takes priority over a fresh one (not applicable here).
6.  **Completion Order Rule**: The final order lists only `LOW` jobs sorted by their absolute finish minute. `HIGH` is excluded from this list.
