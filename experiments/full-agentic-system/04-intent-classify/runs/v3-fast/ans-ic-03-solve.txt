### Phase 1 RULE SCAN
*Listing every rule that changes state during the event or claim list.*

1.  **Grant Rule**: A request arriving at a non-zero pool is granted `min(ask, current_pool)`. State change: Pool decreases by grant amount; Request status becomes "Granted".
2.  **Denial Rule**: A request arriving at an exactly zero pool is denied (listed by ID). State change: Request status becomes "Denied"; Pool remains zero.
3.  **Expiry Trigger Rule**: Upon completion of a specific request (the trigger), any grant associated with that request expires. State change: The system prepares to return tokens based on the expired grant's history.
4.  **Return Calculation Rule**: An expired grant returns `floor(granted_amount / 2)` tokens. State change: Pool increases by returned amount; Request status remains "Granted" (partial grants are never denied).
5.  **Timing Rule**: The return lands immediately before the next request is processed, not after it.
