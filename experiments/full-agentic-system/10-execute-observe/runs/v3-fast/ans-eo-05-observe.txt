### Phase 1 Rule List
Based on the task description and "orientation story" analysis, here are the rules governing state changes:

1.  **Arrival & Granting:** Requests arrive in strict order. If `pool >= ask`, grant full amount (`ask`), reduce pool by `ask`. If `0 < pool < ask`, grant partial amount (`pool`), reduce pool to `0`.
2.  **Denial Condition:** A request is denied (listed by ID) if and only if the pool is exactly `0` upon arrival. Partial grants are never denials; full grants are never denials.
3.  **Expiry Trigger:** The grant associated with Request R2 expires immediately after Request R3 completes (arrives/processed).
4.  **Expiry Return Amount:** Upon expiry, return `floor(granted_amount / 2)` to the pool. This is based on what was *granted* (the partial amount), not what was asked.
5.  **Return Timing:** The expiry return happens immediately after the trigger event (R3) completes and before the next event (R4) arrives.
