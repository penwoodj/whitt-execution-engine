### Analysis of Retry Ladder Failure in Near-Miss Cases

A **near-miss** occurs when an agent's output is technically incorrect or incomplete but semantically close to the target (e.g., missing one specific detail, using slightly wrong terminology, or failing a strict regex check despite logical correctness). The "retry ladder" fails here because:

1.  **Over-Correction vs. Precision:** Standard retry prompts often encourage broad rewrites ("Try again," "Fix this"). In near-miss cases, the agent tends to over-correct, changing valid parts of the answer while trying to fix the minor error, resulting in a worse output or drifting further from the target.
2.  **Lack of Specificity:** The prompt usually lacks explicit instructions on *what* went wrong based on the specific failure mode (e.g., "You missed the date," not just "This is wrong"). Without pinpointing the exact gap, the agent guesses rather than fixes.
3.  **Scope Creep:** If the retry prompt allows the agent to re-evaluate the entire task from scratch without constraints, it may ignore the successful parts of the previous attempt and restart, losing momentum.

### Recommended Changes for a Scoped Replan Prompt

To fix this, the "scoped replan" prompt must be engineered to handle near-misses with surgical precision rather than broad regeneration:

1.  **Explicit Failure Diagnosis:** The prompt should force the agent to first identify the specific nature of the near-miss (e.g., "The output is logically sound but fails the constraint regarding X") before attempting a rewrite.
2.  **Constraint Preservation Instruction:** Include a directive like, "Preserve all correct elements from the previous attempt; only modify the section identified as failing." This prevents over-correction.
3.  **Narrow Scope Definition:** The prompt should explicitly define the scope of the replan (e.g., "Replan only for the missing detail: [Specific Detail]") rather than allowing a full task regeneration.
4.  **Iterative Refinement Tone:** Shift the tone from "Try again" to "Refine this specific aspect," encouraging incremental improvement over radical changes.

**Summary of Change:** The scoped replan prompt must transition from a generic "retry" mechanism to a **"diagnose-and-patch"** mechanism that explicitly isolates the near-miss error and restricts regeneration to only the affected scope, ensuring successful parts are retained.
