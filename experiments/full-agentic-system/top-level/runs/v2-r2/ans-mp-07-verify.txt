### Analysis of Retry Ladder Failure (Near-Miss Cases)

The retry mechanism often struggles with **near-miss** scenarios—cases where the agent's output is mostly correct but contains minor errors or lacks specific precision. The current approach fails because:

1.  **Over-Correction vs. Precision:** Standard retry prompts encourage broad rewrites, causing agents to over-correct and inadvertently change valid parts of the answer while trying to fix minor errors.
2.  **Lack of Specificity:** Prompts lack explicit instructions on what went wrong based on the specific failure mode (e.g., missing a constraint vs. hallucinating an entity), forcing the agent to guess rather than target the exact issue.
3.  **Scope Creep:** Retry prompts allow agents to re-evaluate the entire task from scratch without constraints, causing them to ignore successful parts and restart unnecessarily.

### Recommended Changes for Scoped Replan Prompt

To address these failures in near-miss cases, a "scoped replan prompt" should be modified with the following specific instructions:

1.  **Explicit Failure Diagnosis:** Force the agent to first identify the *specific* nature of the error (e.g., "The output missed constraint X") before attempting any rewrite. This prevents guessing and targets the exact failure mode.
2.  **Constraint Preservation Instruction:** Explicitly instruct the agent to preserve all correct elements from the previous attempt, rewriting only the identified faulty section. This mitigates over-correction.
3.  **Narrow Scope Definition:** Define a strict scope for the replan action (e.g., "Only revise paragraph Y regarding constraint Z"), preventing the agent from re-evaluating the entire task and ignoring successful parts.
