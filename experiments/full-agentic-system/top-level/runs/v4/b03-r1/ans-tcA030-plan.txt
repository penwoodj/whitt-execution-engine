### Step 1: Design Normalized Schema & Rationale (`schema.md`)
**Rule:** Define three tables: `products` (id, name, price_numeric, currency), `suppliers` (id, company_name, contact_info_json), `tags` (product_id, tag_value).  
**Rule:** Enforce strict typing: prices must be floats; names/tags strings max 255 chars.  
**Rationale:** Separation of concerns allows querying suppliers without bloating product rows; JSON storage for supplier details preserves nested data while keeping schema clean.

### Step 2: Load Pipeline with Type Coercion & Error Tracking (`load.py`)
**Rule:** Iterate raw JSON array; skip records where `name` is missing (reject).  
**Rule:** Strip currency symbols ($, €, £) from price strings; convert to float; if conversion fails, reject.  
**Rule:** Split comma-separated tags into individual rows; insert into `tags` table.  
**Rule:** Flatten nested supplier objects into JSON blob for `suppliers` table (or separate row if id exists).  
**Output:** Write `load-report.md` with counts: total_in, rejected_missing_name, rejected_invalid_price, processed_successfully.

### Step 3: Indexing & Timing (`index.py`)
**Rule:** Create index on `products.name` for query 1 (search by name).  
**Rule:** Create composite index on `(tags.product_id, tags.tag_value)` for query 2 (filter by tag).  
**Rule:** Create index on `suppliers.company_name` for query 3 (lookup supplier info).  
**Timing:** Record wall-clock time before and after each CREATE INDEX; output precise milliseconds.

### Step 4: Verification & Conservation Check (`verify.py`)
**Rule:** Re-run the three queries against the loaded DB to confirm results match expected logic.  
**Rule:** Perform conservation check: `total_in` from load report must equal `count(products)` + `rejected_missing_name` + `rejected_invalid_price`.  
**Output:** Generate JSON report with query results, timing table, and conservation delta (must be 0). Exit code 1 if delta != 0.

### Step 5: Documentation & Decisions (`decisions.md`, `rules.md`)
**Rule:** Document all arbitrary thresholds (e.g., max string length) in `rules.md`.  
**Rule:** Record workspace layout decisions and default assumptions in `decisions.md`.  
**Rule:** Ensure all outputs are human-readable Markdown tables AND machine-readable JSON with identical numbers.

### Step 6: Execution & Reproducibility (`run.sh`)
**Rule:** Execute pipeline twice; compare outputs for state consistency (no random seeds unless specified).  
**Rule:** Log one line per stage to `logs/stage_*.txt`.  
**Rule:** Final output directory structure: `/tmp/opencode/jsqlite-run/{schema,load,index,verify,docs}`.
