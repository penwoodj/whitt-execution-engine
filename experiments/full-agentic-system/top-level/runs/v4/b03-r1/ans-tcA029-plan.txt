### Phase 2: Execution & Results

#### 1. Workspace Initialization & Rules Definition

**File: `rules.md`**
```markdown
# Data Merge Rules (Explicit Thresholds)

1. **Trust Hierarchy:** Billing > CRM > Spreadsheet. If a value exists in higher trust, it wins. If missing, check next lower.
2. **Header Normalization:** 
   - `email_address`, `e-mail`, `Email` -> `email`.
   - `name`, `full_name`, `cust_name` -> `name`.
   - `id`, `customer_id` -> `id`.
3. **Data Cleaning:**
   - TSV files: Convert tabs to commas, strip BOM if present.
   - Duplicate Headers: Remove all rows except the first occurrence of a header line.
   - Email Casing: Normalize to lowercase for comparison and storage; preserve original casing in conflict logs only.
4. **Conflict Resolution:** 
   - If values differ after normalization, mark as conflict.
   - Winner value is stored in final output.
   - Loser values are recorded in `conflicts.csv`.
5. **Precision:** No rounding of numeric IDs or timestamps unless specified (none here). Keep full string precision.
6. **Mess Handling:** 
   - Tab-separated file: Flagged as "TSV_MASQUERADER".
   - Duplicated header mid-file: Row flagged as "DUPLICATE_HEADER_ROW".
   - Inconsistent casing: Flagged in conflict log if it caused a mismatch.
```

**File: `mapping.md`**
```markdown
# Header Mapping Table

| Source System | Raw Header(s)          | Canonical Header | Action               |
|---------------|------------------------|------------------|----------------------|
| Billing       | id, name, email        | id, name, email  | Direct Copy          |
| CRM           | customer_id, full_name, email_address | id, name, email | Rename + Trim       |
| Spreadsheet   | cust_id, Name, E-mail  | id, name, email  | Rename + Lowercase   |
```
