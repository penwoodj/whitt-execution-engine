## 3. Workspace Inventory & Architecture

### Directory Structure (`/tmp/opencode/sec-sweep-run`)
```text
/tmp/opencode/sec-sweep-run/
├── README.md              # Workspace layout, decisions, and tone guidelines
├── rules.md               # Detection thresholds (e.g., "Top 20", "Scanner Active")
├── sweep.md               # Stage-by-stage execution plan with numbered steps
├── scripts/
│   ├── pipeline.py        # Main processing logic (Standard Library only)
│   └── verifier.py        # Independent recomputation of metrics from raw inputs
├── outputs/
│   ├── sweep.json         # Final JSON report (Human + Machine compatible)
│   └── logs/              # Per-stage execution logs (one line per stage)
└── raw_data/              # Synthetic fixture data (access_logs.txt)
```

### File Descriptions & Decisions
1.  **`README.md`**: Documents the workspace layout explicitly so structure is a decision, not an accident. Includes tone rules: "Plain sentences," "Tables where tables belong."
2.  **`rules.md`**: Defines thresholds with reasons (e.g., `top_n=20` to ensure coverage even if data is sparse). Explicitly states handling for truncated fields and timestamp drift.
3.  **`sweep.md`**: Numbered stages:
    *   Stage 1: Failed Login Frequency (Top 20).
    *   Stage 2: Path Scanning Detection (Distinct 404 paths).
    *   Stage 3: Admin Hammer Stats (Start/Stop/Rate).
    *   Stage 4: Whitelist Pass (Exclude legitimate crawlers).
4.  **`scripts/pipeline.py`**: Idempotent, self-cleaning. Uses only standard library (`json`, `re`, `datetime`). Handles dirt (truncation, drift) by logging events rather than absorbing them silently.
5.  **`scripts/verifier.py`**: Recomputes key numbers from raw inputs using independent logic. Exits with non-zero code on any mismatch. Currently exits `0`.

### Execution Flow
1.  Run `python scripts/pipeline.py`: Processes `raw_data/access_logs.txt`, generates `outputs/sweep.json` and logs.
2.  Run `python scripts/verifier.py`: Reads raw data, recomputes metrics, compares with `outputs/sweep.json`.
3.  Check exit code of verifier (must be `0`).

### Where This Would Break First Under Stress
*   **State Bugs:** If the pipeline were not self-cleaning and ran twice without clearing intermediate state, counts might double. (Mitigated by explicit cleanup in `pipeline.py`).
*   **Truncated Data:** If truncation logic changes or new truncation patterns emerge, the current regex-based handling might fail silently unless logged events are audited.
*   **Timestamp Drift:** If drift exceeds a certain threshold (e.g., > 1 hour), simple aggregation across files might misalign events; currently handled by logging max delta.
