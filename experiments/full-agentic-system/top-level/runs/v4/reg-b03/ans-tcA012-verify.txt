### 2. Explicit Rules (`data/rules.md`)
These rules define how the pipeline interprets the raw data, specifically addressing the "missing check" edge case and burn rate thresholds.

1.  **Missing Checks vs Failed Checks**: A missing check (null/empty timestamp) is treated as *zero downtime* for that minute but contributes to the denominator of availability calculation only if it falls within scheduled hours. It does not count as an error event.
2.  **Availability Calculation**: `Availability = (Total Minutes - Downtime Minutes) / Total Scheduled Minutes`. Missing checks are excluded from "Downtime" but included in "Scheduled" if they occur during business hours.
3.  **Burn Rate Threshold**: A day is flagged as "Critical Burn" (>3x sustainable burn) if `Daily Error Budget Consumed > 3 * (Monthly Error Budget / 30)`.
4.  **Precision**: All numbers are stored with full floating-point precision. No rounding to integers or two decimal places unless explicitly requested for display in markdown tables (where up to 6 decimals are shown).
5.  **Edge Case Handling**: Any day where `Downtime > 0` AND `Missing Checks > 0` is logged separately to distinguish between "slow grind" and "one bad hour".

### 3. Decisions (`decisions/decisions.txt`)
Rationale for specific implementation choices made during the run.

*   **Handling Missing Data**: The raw data simulates a scenario where `service_c` has missing checks on Day 9. Decision: Treat these as non-failed minutes but ensure they are counted in the denominator of availability to avoid inflating the percentage artificially.
*   **Burn Rate Calculation**: Sustainable burn is calculated as `(Monthly Error Budget) / 30`. If a day consumes more than `3 * Sustainable Burn`, it triggers a flag. This aligns with the requirement to identify "how fast you eat monthly error budget".
*   **Verification Logic**: The verifier script (`verify.sh`) does not import the pipeline's code. It recomputes availability and burn rates from scratch using only the raw JSON data and the rules defined in `rules.md`. If results differ, it exits with a non-zero code.
