# Decisions Log (`decisions.md`)

**1. Repeat Normalization Strategy:**
*   **Rule:** For each scenario per commit, calculate `best` (minimum time) and `median`. Use `best` for regression detection to be conservative against noise spikes; use `median` for reporting stability.
*   **Reasoning:** The prompt specifies "normalize repeats into best-and-median". Using the minimum ensures we don't flag a regression caused by a single outlier spike, while the median provides a robust baseline for trend analysis.

**2. Regression Threshold Application:**
*   **Rule:** A scenario is flagged as regressing if: `(Current_Best - Previous_Best) / Previous_Best > 0.10`.
*   **Reasoning:** Matches "slowing more than 10 percent commit-over-commit". Denominator is always the *previous* commit's best time to measure growth relative to the baseline performance.

**3. Pure Refactor Audit Logic:**
*   **Rule:** The specific commit claimed as "pure refactor" (Commit #5) will be audited by comparing its `median` times against the global median of all scenarios in that commit. If any scenario deviates >10% from the commit's own baseline, it is flagged as non-pure-refactor.
*   **Reasoning:** Matches "timing says otherwise". A refactor should ideally show consistent or improved performance across all scenarios; significant variance indicates logic changes elsewhere.

**4. Timestamp Ambiguity Handling:**
*   **Rule:** If two commits share a timestamp, order them by `commit_id` (ascending).
*   **Reasoning:** Matches "two commits share timestamp making order ambiguous". Deterministic tie-breaking is required for reproducible delta calculations.

**5. Single Repeat Scenario Handling:**
*   **Rule:** If a scenario has only one repeat, that single value is used as both `best` and `median`. No normalization adjustment is made.
*   **Reasoning:** Matches "one scenario has only one repeat". Cannot calculate median or best from N=1; must accept the raw data point.

**6. Outlier Spikes Disposition:**
*   **Rule:** Values identified as outliers (e.g., >2 standard deviations from commit median) are included in regression calculations but annotated with `[OUTLIER]` in the output table. They do not trigger a "Quarantine" unless they cause a false positive on the *median*.
*   **Reasoning:** Matches "timings have outlier spikes... every one of those needs documented disposition". We document them rather than silently dropping them to maintain data integrity traceability.

**7. Verdict Calculation Order:**
*   **Rule:** Stage 1 (Normalize) -> Stage 2 (Delta/Regression) -> Stage 3 (Verdicts).
*   **Reasoning:** Matches "stage by stage". This order ensures normalization feeds the delta calculation, which feeds the verdict logic.

**8. Output Format Consistency:**
*   **Rule:** Markdown tables and JSON objects will use identical numeric precision (4 decimal places) to ensure zero drift between human-readable and machine-parseable outputs.
*   **Reasoning:** Matches "same numbers, no drift".

# Rules Definition (`rules.md`)

**Rule R-01: Repeat Normalization**
*   **Definition:** `Best` = MIN(Time), `Median` = MEDIAN(Time).
*   **Exception:** If `Count == 1`, then `Best == Median`.
*   **Threshold:** N/A.

**Rule R-02: Regression Detection**
*   **Definition:** `(Current_Best - Previous_Best) / Previous_Best > 0.10`.
*   **Denominator:** Always `Previous_Best` (Commit-N).
*   **Exception:** Outliers are included but tagged `[OUTLIER]`.

**Rule R-03: Refactor Audit**
*   **Definition:** Compare Scenario Best against Commit Median.
*   **Threshold:** Deviation > 10% triggers `FAIL` verdict for "Pure Refactor" claim.

**Rule R-04: Timestamp Tie-Breaking**
*   **Definition:** If `Timestamp_A == Timestamp_B`, sort by `Commit_ID` ASC.

**Rule R-05: Output Consistency**
*   **Definition:** Markdown tables and JSON must use identical numeric precision (4 decimals).
*   **Reason:** Prevents drift between human and machine verification.
