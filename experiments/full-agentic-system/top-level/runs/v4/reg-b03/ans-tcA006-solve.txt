### 2. `rules.md`
```markdown
# Processing Rules & Thresholds

1. **Suspicion Flag**: A test is flagged as suspicious if its pass rate is between 5% and 95%.
   - *Reason*: Purely passing (100%) or purely failing (0%) tests are stable; intermediate rates indicate instability.
2. **Failure Cluster Definition**: Consecutive failures in the build log for a specific test constitute a cluster.
3. **Correlation Check**: Pearson correlation coefficient calculated between pass/fail binary vectors of two tests. No rounding applied to preserve precision.
4. **Confidence Note**: Derived from the number of observations (builds) where the test was flagged as suspicious. Higher observation count = higher confidence in the flake status.
5. **Duplicate Handling**: Records with identical content but different IDs are treated as distinct events unless explicitly merged by a rule; here, they are logged separately to detect data integrity issues.
6. **Missing Field Handling**: Builds missing test fields are skipped for pass-rate calculation but logged as errors in the stage log.
```

### 3. `data.py`
```python
import json
import random

# Fixed seed for deterministic universe
random.seed(42)

def generate_builds():
    builds = []
    
    # Simulate 500 builds over a month (approx 16 days, ~30 builds/day)
    # We will generate exactly 500 records with specific anomalies
    
    test_names = [f"test_{i}" for i in range(40)]
    
    # Define pass rates for tests to simulate flakiness
    # test_retry_loop is the prime suspect (highly fluctuating)
    base_rates = {
        "test_retry_loop": random.uniform(0.3, 0.7), # Highly unstable
        **{t: random.uniform(0.95, 1.0) for t in ["test_stable_1", "test_stable_2"]},
        **{t: random.uniform(0.4, 0.6) for t in test_names[3:]}, # Some moderately flaky
    }

    current_date = "2023-10-01"
    
    for i in range(500):
        build_id = f"B{i:04d}"
        
        # Anomaly 1: Duplicates with different IDs (simulated by reusing content)
        if random.random() < 0.05 and len(builds) > 50:
            prev_build = builds[-1]
            build_id = f"B{random.randint(600, 999):04d}" # Fake new ID for duplicate
            content = json.loads(prev_build['content'])
        else:
            content = {}
            
        # Anomaly 2: Missing test fields entirely (3 builds)
        if i in [150, 320, 480]:
            content = None
            
        # Generate results for this build based on base rates + noise
        results = []
        if content is not None:
            for t_name in test_names:
                rate = base_rates.get(t_name, 0.5)
                # Add noise to simulate flakiness
                actual_pass = random.random() < (rate + random.uniform(-0.1, 0.1))
                results.append({"test": t_name, "passed": actual_pass})
        
        build_record = {
            "build_id": build_id,
            "timestamp": f"{current_date}T{random.randint(0, 23):02d}:{random.randint(0, 59):02d}:00Z",
            "content": json.dumps(results) if results else None,
            "status": "success" # CI overall success, but tests may fail
        }
        
        builds.append(build_record)
        
        # Advance date occasionally to simulate month span
        if i % 30 == 0:
            current_date = f"{int(current_date.split('-')[2])+1}-01"

    return builds

if __name__ == "__main__":
    data = generate_builds()
    with open("output/raw_data.json", "w") as f:
        json.dump(data, f)
```
