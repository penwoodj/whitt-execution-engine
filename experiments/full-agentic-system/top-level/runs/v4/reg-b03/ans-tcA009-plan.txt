### PLAN FIRST: Analysis Pipeline Steps

1. **Initialize Workspace & Rules**: Create directory structure (`/tmp/opencode/trace-run`), write `rules.md`, `README.md`, and logging setup scripts to define idempotent behavior, error handling, and artifact paths.
2. **Load Raw Traces**: Parse all 300 JSON trace files from the workspace root into a unified in-memory representation (or temporary staging area) while validating basic structure (root span existence).
3. **Sanitize & Flag Anomalies**: Iterate through spans to detect illegal overlaps, negative durations, and orphan spans; record these violations with specific span IDs and reasons in an anomaly log.
4. **Compute Span Metrics (Stage 1)**: Calculate per-span-name average self-time and p99 self-time excluding children for all valid spans; output `outputs/span_metrics.csv` and `outputs/span_metrics.json`.
5. **Identify Top Traces (Stage 2 Prep)**: Sum total duration per trace, sort descending, select the top 3 traces by depth/duration, and prepare their span trees for waterfall visualization.
6. **Generate Waterfalls (Stage 2 Output)**: Render indented text lists of spans for the top 3 traces with precise timestamps; output `outputs/waterfall_top3.txt` and `outputs/waterfall_top3.json`.
7. **Identify Global Slow Span (Stage 3 Prep)**: Aggregate total time spent in each span name across all traces to find the single slowest span name and its global percentage of total system time.
8. **Generate Slow Span Report (Stage 3 Output)**: Output `outputs/slow_span.txt` and `outputs/slow_span.json` containing the slowest span name, precise duration, and percentage with denominator.
9. **Compute Status Breakdown (Stage 4)**: Count success/fail occurrences per span name; output `outputs/status_breakdown.csv` and `outputs/status_breakdown.json`.
10. **Generate Waterfall Report Files (Stage 5 Output)**: Combine human-readable markdown (`waterfall.md`) and machine-verifiable JSON (`waterfall.json`) containing the top 3 waterfalls, slow span stats, and status breakdown; ensure both files have identical numeric content.
11. **Run Verification Script**: Execute an independent checker script that re-computes all metrics from raw trace files without using pipeline outputs, compares against `outputs/` files, logs discrepancies, and exits with non-zero code if any mismatch exists.
12. **Generate Final Report & Timing Table**: Create `report.md` summarizing findings, file paths, anomaly counts, and a timing table of all stages; include notes on data contradictions or rule adjustments.
