### 2. Rules & Decisions (`rules.md` & `decisions.txt`)

**Rules (`rules.md`):**
1.  **Timezone Normalization:** All timestamps must be converted to UTC for sorting. Local offsets are parsed from log headers or inferred if missing (defaulting to +00:00).
2.  **Gap Handling:** Any sequence break > 30 seconds in the merged stream is flagged as a `DATA_GAP`. A specific event type `GAP` is inserted with message "Missing data between [T1] and [T2]" if raw logs are silent.
3.  **Detection Threshold:** An event is considered "Detected" only when an error level log appears in the API Gateway or Auth Service within a 60-second window of the first anomaly signal.
4.  **Mitigation Success Criteria:**
    *   Attempt 1 (Restart): Succeeds if `db-primary` logs show connection restored AND no new errors for 3 minutes.
    *   Attempt 2 (Failover): Succeeds if `api-gateway` logs switch to pointing at a secondary DB host and latency drops below threshold.
5.  **Error Reporting:** Error messages must include the specific failure code or reason string, not generic "error".

**Decisions (`decisions.txt`):**
*   **Default Offset:** If a log header lacks an offset, assume UTC (+00:00).
*   **Gap Fill Content:** Gaps are filled with metadata only (timestamps), no synthetic messages.
*   **Service Count:** 6 services confirmed in input simulation.
