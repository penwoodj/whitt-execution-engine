Phase 1 RULE SCAN:

- Rule: User count increases from 10 to 1000 over 30 minutes. Trigger: Ramp start (t=0).  
- Rule: Throughput sampling begins every 10 seconds during ramp phase. Trigger: First sample at t=10s.  
- Rule: P95 latency starts being recorded every 10 seconds from ramp onset. Trigger: First latency sample at t=10s.  
- Rule: Error rate sampling begins every 10 seconds during ramp phase. Trigger: First error sample at t=10s.  
- Rule: Graceful degradation threshold is set at 600 users; if throughput drops below 80% of baseline after this point, degradation is declared active. Trigger: User count reaches 600 (t ≈ 24 minutes).  
- Rule: If latency growth rate exceeds throughput growth rate by more than 15%, a knee point is detected. Trigger: Any sample where d(latency)/dt > d(throughput)/dt + 0.15 (in units per second).  
- Rule: Error taxonomy rule activates when error % exceeds 2% of total requests; errors are categorized as client timeout, server timeout, or internal error. Trigger: Error rate ≥ 2% at any sample point.  
- Rule: If two counters reset mid-run (e.g., request count resets to zero), a data corruption flag is set and logged. Trigger: Any row where request_count == 0 after non-zero prior value.  
- Rule: Units inconsistency rule triggers when throughput units are in "requests/sec" but latency is in "ms", or error rate is given without denominator. Trigger: Unit mismatch detected in any sample row.  
- Rule: If a sample has missing data (e.g., no throughput, no p95), the sample is marked as invalid and skipped; system state remains unchanged. Trigger: Missing field in any sample row.  
- Rule: On detection of a reset or inconsistency, a fallback rule reverts to baseline values for that metric until next valid sample. Trigger: Reset or unit mismatch detected.  
- Rule: If degradation claim fails (i.e., throughput does not drop after 600 users), the system is declared non-graceful and a failure verdict is issued. Trigger: User count ≥ 600 AND throughput ≥ 85% of baseline at any point post-600.  
- Rule: If latency climbs faster than throughput by more than 15%, a knee point is recorded with timestamp, user count, and metric values. Trigger: Same as degradation rule (latency growth > throughput growth + 15%).  
- Rule: Source-ranking rule: if p95 latency exceeds 200ms at any sample, the source of the request is ranked by error rate; this ranking is used to prioritize recovery actions. Trigger: p95 ≥ 200ms.
