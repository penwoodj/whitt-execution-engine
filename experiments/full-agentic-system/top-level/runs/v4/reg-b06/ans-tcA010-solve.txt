Phase 1 RULE SCAN:

- Rule: If consumer offset is greater than log end offset by more than 30 seconds, mark as lagging. Triggered by every lag snapshot event.  
- Rule: If a rebalance event occurs at timestamp T, flag all lag snapshots from T–5 minutes to T+5 minutes as "rebalance-influenced". Triggered by rebalance event.  
- Rule: If lag exceeds 60 seconds for any partition in worker-2, classify burst window and record start/end timestamps. Triggered by lag snapshot with worker-2.  
- Rule: If offset goes backwards (i.e., new offset < previous offset), flag as invalid and log error. Triggered by any offset update event.  
- Rule: If a rebalance occurs and the consumer is worker-2, mark all lag snapshots during that rebalance as "rebalance-triggered". Triggered by rebalance event with worker-2 involved.  
- Rule: If mean lag across partitions exceeds 10 seconds for more than two consecutive minutes, trigger burst detection. Triggered by every minute snapshot.  
- Rule: If max lag in any partition exceeds 300 seconds, mark as critical and record timestamp. Triggered by any lag snapshot with max lag > 300s.  
- Rule: On arrival of a rebalance event, reset all consumer lag metrics to zero for that consumer. Triggered by rebalance event.  
- Rule: If a refill event occurs (e.g., message count increases due to refill), adjust throughput estimate upward by 15%. Triggered by refill event.  
- Rule: On fallback to backup consumer, set worker-2 lag as "fallback-lag" and mark with source ranking of 0.3. Triggered by fallback event.  
- Rule: If a promotion occurs (e.g., new consumer takes over), update source ranking for that consumer to 1.0 and reset lag metrics. Triggered by promotion event.  
- Rule: On expiry of a rebalance window, return all lag data to pre-rebalance state. Triggered by expiry timestamp after rebalance.
