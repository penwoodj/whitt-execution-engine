# RULES FILE: rules.md

## Rule: Install-without-clean detection (threshold: >1.5GB)
- **Why**: APT installs large packages without a `rm -rf` or cleanup command are classic bloat sources.
- **Threshold**: Any layer with size > 1.5 GB and containing an `apt-get install` command is flagged.
- **Exception**: If the layer contains `apt-get clean`, it is not flagged — this is a known cleanup step.

## Rule: Duplicated data adds
- **Why**: Repeatedly adding same files (e.g., `/etc/hosts`) without removal creates redundant layers.
- **Rule**: If two consecutive layers have identical file paths and the same content hash (via `diff`), flag as duplicated data add.
- **Threshold**: Only applies to layers with size > 100MB — smaller layers are assumed to be noise.

## Rule: Secrets in layer
- **Why**: Secrets like passwords or keys in layers can leak if not properly masked or removed.
- **Rule**: Flag any layer that contains a string matching `/etc/secret`, `password=`, `key=`, or `token=` (case-insensitive).
- **Threshold**: Any such match, regardless of size.

## Rule: Cumulative size correction
- **Why**: Raw dump has two spots where cumulative size is duplicated — one in layer 12 and one in layer 30.
- **Action**: Correct both by subtracting the prior layer’s size from the current layer's cumulative value to get true layer size.
- **Log entry**: "Corrected cumulative size at index 12: original=5.4GB, corrected=3.8GB; index 30: original=9.1GB, corrected=7.6GB"

## Rule: Zero-size layer handling
- **Why**: A zero-size layer does metadata-only work (e.g., `RUN mkdir /tmp` with no files).
- **Action**: Flag it as "metadata-only" and include in the table with size=0.
- **Note**: It is not removed — it contributes to history but adds no weight.
