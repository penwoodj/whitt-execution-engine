Phase 1 RULE SCAN:

- Rule: On arrival of an event with a key that already has a record, if the payload is identical to the existing one, suppress the retry and mark as healthy duplicate. Triggered by: order arrival with matching key and payload.
- Rule: On arrival of an event with a key that already has a record, if the payload differs, flag as suspicious collision and trigger human review. Triggered by: order arrival with same key but different payload.
- Rule: Upon detection of a key with five or more distinct payloads, mark all such entries for manual audit and log in flagged-collisions.csv. Triggered by: group-by-key aggregation showing ≥5 unique payloads per key.
- Rule: When a key appears with the same order payload under two different keys, flag both records as collision and record in flagged-collisions.csv. Triggered by: cross-key payload match detection during grouping.
- Rule: If any key has more than one entry with identical payload but different timestamps (within 10 minutes), classify as potential clock-skew and log the entries. Triggered by: timestamp-based delta check on same-payload entries.
- Rule: On completion of group-by-key analysis, count total suppressed duplicates and report percentage of original attempts that were suppressed. Denominator is total number of order attempts (raw input rows). Triggered by: post-grouping suppression tally.
- Rule: If a key has more than one entry with the same payload but different order IDs, trigger collision flag and log in flagged-collisions.csv. Triggered by: duplicate payload across distinct order IDs.
- Rule: On detection of any row where a key appears with five or more payloads (including duplicates), emit an error message stating "key has ≥5 payloads" and halt processing. Triggered by: group-by-key count exceeding 4.
- Rule: If the number of suspicious collisions exceeds 10% of total order attempts, trigger alert and log in logs.txt. Denominator is total input rows. Triggered by: collision count > (total_rows × 0.10).
- Rule: On any row where a key appears with a payload that matches an existing one but the timestamp is more than 30 minutes apart, flag as potential data drift and log in logs.txt. Triggered by: timestamp delta > 30 minutes.
- Rule: If two different keys map to the same order payload (same content), mark both entries as collision and include in flagged-collisions.csv. Triggered by: payload-level cross-key match detection.
- Rule: After all events are processed, compute collision frequency over time (per day) and output actual daily counts with cumulative totals. Triggered by: chronological ordering of order events.
- Rule: If any stage produces a result that contradicts the stated background (e.g., key appears with five payloads but not in input), report contradiction explicitly in logs.txt. Triggered by: data inconsistency check against background claim.
- Rule: On final output generation, verify all numbers using a standalone verifier script that reprocesses raw inputs and computes counts independently. Triggered by: post-processing stage.
- Rule: If the verifier finds any mismatch between computed values and stored outputs, exit with non-zero status and log error in verification.log. Triggered by: verifier script execution result.
- Rule: When a rule is triggered and conflicts with an input row (e.g., rule says "flag" but row has no variation), include both the row and the rule in flagged-output.json. Triggered by: rule-row disagreement during processing.
