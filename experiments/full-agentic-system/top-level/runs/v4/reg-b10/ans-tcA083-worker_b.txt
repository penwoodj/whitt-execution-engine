Phase 1 RULE SCAN:

- On request arrival at timestamp t, if bucket tokens < request weight, reject the request. Triggered by every request event in the trace.
- If bucket tokens ≥ request weight, serve the full request and deduct tokens; update bucket state. Triggered by every request event in the trace.
- After each refill cycle (every 1 second), add 10 tokens to bucket if not already at capacity (max 100). Triggered by every second boundary in the timeline.
- If a request has weight zero, serve it immediately with no token cost and do not update bucket state. Triggered by any request with weight == 0.
- If a timestamp is out of order (later than previous event), treat as invalid and reject the request; log the inconsistency. Triggered by any request with timestamp > prior request timestamp.
- On fractional millisecond weights, round to nearest integer (round half up). Triggered by every request with non-integer weight.
- If bucket tokens become negative during serving, cap at zero and mark as partial serve with remaining token deficit. Triggered when serving a request exceeds available tokens.
- After each request, if the bucket is below 10 tokens and no refill has occurred in the last second, trigger a fallback to 5 tokens (source-ranking rule). Triggered by every request after bucket < 10 and no refill in past second.
- If a refill occurs during a burst and bucket reaches capacity, cap refill at capacity. Triggered when refill would exceed capacity.
- On any request that causes bucket to go below zero, record as edge case and log the state before and after. Triggered by every request with token deficit.
