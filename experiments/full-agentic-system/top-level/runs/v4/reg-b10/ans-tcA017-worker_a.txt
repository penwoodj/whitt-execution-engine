Phase 1 RULE SCAN:

- Rule: Suppress duplicate retry with same idempotency key and identical order payload. Triggered by event: OrderRetry (same key, same payload).  
- Rule: Flag suspicious collision when same idempotency key has different order payloads. Triggered by event: OrderRetry (same key, different payload).  
- Rule: Mark all collisions for human review with both payloads side-by-side. Triggered by event: CollisionDetected (key collision found).  
- Rule: Count suppressed duplicates to prevent double charging. Triggered by event: DuplicateSuppressed (same key, same payload).  
- Rule: Compute and record collision frequency over time per day. Triggered by event: DailyCollisionLog (daily count of collisions).  
- Rule: Flag any order payload appearing under two different keys. Triggered by event: PayloadKeyMismatch (payload appears with multiple keys).  
- Rule: Log each row where key collision contradicts background claim. Triggered by event: ContradictionFound (data contradicts stated rules).  
- Rule: Apply fallback to default state if no idempotency rule matches. Triggered by event: FallbackApplied (no matching rule found for retry).  
- Rule: Revocate a key after 30 days of inactivity. Triggered by event: KeyInactivityExpiry (key not used in 30 days).  
- Rule: Return idempotency state to initial if retry fails with no payload. Triggered by event: RetryFailureNoPayload (retry fails, no order data).  
- Rule: Refill key pool after 10,000 charge attempts per key. Triggered by event: KeyAttemptCountExceeded (key reaches 10,000 attempts).  
- Rule: Promote a key to high-priority if it has been used in 5+ successful retries. Triggered by event: HighRetriesDetected (key with ≥5 successful retries).  
- Rule: Source-ranking rule: assign priority to keys based on first occurrence time. Triggered by event: KeyFirstOccurrence (first use of key).
