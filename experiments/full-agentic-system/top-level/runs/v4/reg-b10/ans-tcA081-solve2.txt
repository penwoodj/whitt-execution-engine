Phase 1 RULE SCAN:

- Rule: Install-without-clean detection triggers when a layer contains apt-get install or similar package installer command with no subsequent remove or cleanup.  
  Trigger: Any layer with "apt-get install" or equivalent followed by no removal in later layers, AND the layer is not marked as metadata-only.  
  Reason: This pattern adds bloat that persists; threshold = 10% of cumulative size if repeated across multiple layers.

- Rule: Duplicated data adds detection triggers when a layer contains identical file paths or content hashes (via checksum comparison) to a prior layer, and the later layer does not remove or overwrite.  
  Trigger: File path or content hash match between two layers with no intervening removal.  
  Reason: Redundant data increases size without functional benefit; threshold = 5% of cumulative size if repeated.

- Rule: Secrets-in-layer detection triggers when a layer contains any string that matches known secret patterns (e.g., API keys, passwords) in command or file content.  
  Trigger: Any layer with text matching regex pattern for secrets (e.g., "password=xxx", "token=abc123").  
  Reason: Security risk; threshold = 100% of layer size if present.

- Rule: Add-then-remove pair detection triggers when a layer adds data (via command or file) and a later layer removes it via rm -rf, delete, or equivalent.  
  Trigger: A layer with file creation or data addition followed by a later layer removing that same path or content.  
  Reason: Net-zero weight but high history cost; threshold = any such pair where the added size > 0.

- Rule: Refill rule triggers when a layer is rebuilt from scratch (e.g., new base image) and contains identical commands to a prior layer, indicating redundant work.  
  Trigger: Layer command matches previous layer exactly in sequence and content.  
  Reason: Redundant execution; threshold = cumulative size > 10% of total if repeated.

- Rule: Expiry rule triggers when a layer is marked as "expired" or "obsolete" by metadata (e.g., timestamp older than 7 days).  
  Trigger: Layer has timestamp older than  or no timestamp at all.  
  Reason: Outdated layers should be pruned; threshold = 10% of cumulative size if expired and unused.

- Rule: Return rule triggers when a layer is marked as "return" in metadata (e.g., rollback, revert).  
  Trigger: Layer has "return" flag or command like "rollback to layer X".  
  Reason: Indicates state reversion; threshold = any such layer with size > 0.

- Rule: Fallback rule triggers when a layer contains fallback logic (e.g., "if not found, use default") and the default is not actually used.  
  Trigger: Layer has conditional command with fallback path but no evidence of actual fallback execution.  
  Reason: Wasted computation; threshold = 15% of cumulative size if unused.

- Rule: Source-ranking rule triggers when a layer's source (e.g., base image, build step) is ranked lower than previous layers in dependency graph.  
  Trigger: Layer has source with lower priority or no explicit dependency path.  
  Reason: May indicate poor optimization; threshold = any such layer where size > cumulative total * 0.1.

- Rule: Promotion rule triggers when a layer is promoted to "production" status via metadata flag.  
  Trigger: Layer has "promoted=true" in metadata.  
  Reason: Indicates active use; threshold = only if used by downstream layers.
