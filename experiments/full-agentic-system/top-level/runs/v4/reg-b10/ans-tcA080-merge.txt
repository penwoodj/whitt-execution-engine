  Trigger: After all dependencies are classified by type, a compliance check runs per project and per class.  

- Rule: Flag violations by class with violation type (exact mismatch, caret allowed, commit missing).  
  Trigger: Policy check completes; any dep violating policy is recorded as a violation with its class and project.  

- Rule: Check existence of pinned version in versions index file for each pin.  
  Trigger: After all dependencies are processed and classified, each pinned version is checked against the versions index.  

- Rule: Identify typo-pin — when a pinned version does not exist in the versions index.  
  Trigger: Version existence check fails; this triggers a "typo-pin" violation per dependency with invalid version.  

- Rule: Compute per-project compliance score as (compliant deps / total deps) × 100, for each project.  
  Trigger: After all violations are recorded and classified by project.  

- Rule: Generate overall league table of projects ranked by compliance score descending.  
  Trigger: All per-project scores computed; sorting occurs after scoring is complete.  

- Rule: Surface data inconsistencies — e.g., inconsistent section naming, nested manifests, missing versions in index.  
  Trigger: During manifest parsing and version lookup; any deviation from expected structure is logged with the rule that detected it.  

- Rule: Flag every row where policy and rule disagree (e.g., a dev dep pinned exactly when policy allows caret).  
  Trigger: Policy check runs per dependency; if actual pin violates stated policy, both the row and the rule are output side-by-side.  

- Rule: Verify outputs by recomputing key metrics from raw inputs using standalone logic.  
  Trigger: After all stages complete; verifier script runs independently to validate scores, counts, and violations.

  Trigger: After each stage completes, outputs are written to file system with consistent naming.  

- Rule: Final report must include both human-readable markdown and machine-readable JSON with identical numbers.  
  Trigger: After all stages complete; verification confirms consistency between formats.  

- Rule: All error messages must specify what failed and where (file, line, rule).  
  Trigger: Any failure during parsing or validation triggers a message with full context.  

- Rule: Percentages must include denominator (e.g., "12% of 87 deps").
