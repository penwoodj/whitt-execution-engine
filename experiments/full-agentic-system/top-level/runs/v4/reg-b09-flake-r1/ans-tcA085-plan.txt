```plaintext
PLAN:

1. Initialize workspace: mkdir -p /tmp/opencode/sched-run/{data,logs,outputs,rules}
2. Load input data into memory: 60 jobs with arrival, duration, priority (high/medium/low)
3. Preprocess aging rule: for each job, track age in minutes; if age >= 10, bump priority level
4. Apply manual priority reassignment flag to one job at specified minute (flagged entry)
5. For each job, compute original start time and duration; store as (arrive, dur, prio)
6. Simulate per-minute walk from m=0 upward:
   - At each minute m, check if any LOW is ready to run (core available and waiting)
   - If a LOW is ready, assign core to it: record start s = m, duration d
   - If no LOW ready, core idles — but rule 2 forbids idle; thus, core must be assigned to the LOW with smallest original start minute (tie-breaker: resumed > fresh)
7. For each LOW job:
   - On assignment at minute s, compute finish time = s + d
   - Bank checkpoints at: s+2 and every 2 RUNNING minutes after (absolute), including if on HIGH arrival
8. Track preemption events:
   - When a higher-priority job arrives before a lower one, preempt the lower
   - On preemption, wasted += minutes run past last bank; owed = d − banked
9. After each preemption, resume job at finish minute of previous job (same minute as next LOW start)
10. Compute makespan: max(finish time over all jobs including HIGH)
11. Order LOW jobs by finish time only
12. Sum total wasted minutes across all preemptions
13. Log aging events: list each bump with job ID, original priority, new priority, age at bump
14. Run no-aging rerun (same input but skip aging rule) to compare starvation counts
15. Generate human-readable table of per-minute state: who runs, who waits, who resumes
16. Generate wait-time stats per priority class: mean, median, min, max, count for each class
17. Generate fairness report: starved jobs (waited > 0 and never got core), count by priority
18. Write stage-by-stage outputs:
    - sched.md: human-readable walk with minute-by-minute assignments
    - walk.csv: per-minute state table (m, running job, waiting jobs)
    - fairness.json: {starved_by_prio: {...}, wait_times: {...}}
19. Cache all raw inputs and intermediate states in /tmp/opencode/sched-run/data/
20. Write rules.md with full rule definitions including thresholds
21. Create decisions.txt: list defaults (e.g., tie-breaker, aging threshold)
22. Run verifier script independently to recompute key metrics from raw input
23. Verify all outputs match verifier output; exit non-zero if mismatch
24. Log each data defect:
    - Clock-skewed entries: detect and correct; count and list in log.txt
    - Duration zero job: mark, skip, log
    - Identical arrival jobs: resolve tie with rule (resumed > fresh)
25. Final output: human markdown table + machine JSON, both identical
26. One honest surprise: a discovered inconsistency between input and implied behavior
27. All artifacts exist on disk; no hidden state or cache
28. Every number in final report traces back to raw input row
29. No rounding; all times precise to minute
30. If rule feels arbitrary, annotate with threshold and reason
31. Output verification: verifier script runs independently, exits non-zero if mismatch
32. Final state: verified outputs, readable structure, timing logs per stage
```
