### 1. Directory Structure & Rules
First, we define the directory layout and the rules governing the pipeline behavior. This ensures reproducibility and clarity for future maintenance.

**Directory Layout:**
```text
/tmp/opencode/warehouse-test/
├── fixtures/          # Raw input data (generated)
│   ├── inbound/       # Valid records + malformed ones
│   ├── outbound/      # Valid records + malformed ones
│   ├── quarantined/   # Valid records + malformed ones
│   └── archived/      # Valid records + malformed ones
├── scripts/           # Processing logic
│   ├── generate_fixtures.py
│   ├── pipeline.py    # Main processing (scan, dedupe, report)
│   └── verify.py      # Independent verification script
├── rejects/           # Malformed files output
├── review/            # Duplicate candidates output
├── reports/           # Final outputs
│   ├── warehouse-report.md
│   └── warehouse-report.json
└── logs/              # Processing logs
```

**Rules:**
1.  **Input Handling**: All four subfolders (`inbound`, `outbound`, `quarantined`, `archived`) are scanned. Valid JSON records are processed; malformed ones (syntax errors) are moved to `rejects` with a reason file.
2.  **Deduplication Logic**:
    *   **Exact ID Match**: If the same `part_id` appears twice, the record with the newer file modification time is kept. The "loser" is logged but not rejected (it's valid data).
    *   **Semantic Duplicate**: If two records have the exact same `part_name` and `category` but different quantities or costs, they are flagged as potential duplicates in a `review` folder for human inspection.
3.  **Reporting**: The report calculates totals based on the deduplicated set (excluding semantic duplicates from the final count to avoid double-counting value).
4.  **Verification**: A separate script recomputes all metrics from raw files and compares them against the generated reports. It exits with a non-zero code if any mismatch is found.
5.  **Efficiency**: The pipeline uses standard file I/O operations optimized for sequential processing to ensure consistent timing across runs.
