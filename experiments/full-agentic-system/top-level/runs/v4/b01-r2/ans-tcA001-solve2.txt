### Phase 1 RULE SCAN

This phase identifies the logical rules governing state changes based on the `TASK REQUIREMENTS` provided for the inventory pipeline. Since this is a file-system processing task rather than a database ledger, "state" refers to the lifecycle of an input record (File -> Manifest/Reject) and the aggregation logic (Deduplication, Reporting).

**Rule List:**
1.  **Malformed File Rule**: If a JSON file fails parsing or validation (missing comma, trailing brace), state changes from `Pending` to `Rejected`; triggers: Stage 1 Scan; output: `rejects/<filename>.<reason>`.
2.  **Exact Part ID Dedup Rule**: If two valid records share the exact same `part_id`, state changes for the older file (by modification time) from `Valid` to `Duplicate_Loser`; triggers: Stage 2 Dedupe; output: Log entry identifying loser.
3.  **Semantic Duplicate Flag Rule**: If two valid records share the same `part_name` AND `category` but have different `quantity_on_hand`, state changes for both from `Valid` to `Review_Candidate`; triggers: Stage 2 Dedupe; output: File moved/copied to `review/`.
4.  **Aggregation Rule**: State of all valid records transitions from `Individual` to `Aggregated` in the final report; triggers: Stage 3 Report; logic: Sum quantities, sum values (`qty * cost`).
5.  **Defective Rate Calculation Rule**: State of `status == 'defective'` records is isolated for percentage calculation; triggers: Stage 3 Report; output: Metric field.
