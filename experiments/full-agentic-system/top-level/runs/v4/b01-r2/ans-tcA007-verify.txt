# Alert Storm Deduplication Pipeline: Final Report & Artifacts

## Executive Summary
The pipeline successfully processed a simulated alert storm (2000 alerts) containing deliberate data quality issues (mixed timestamps, out-of-order events, noise makers). The system grouped 15 distinct incidents from the raw input, normalized severities (including correcting one all-caps typo), and identified high-frequency "noise maker" patterns. All artifacts are located in `/tmp/opencode/alert-run`.

**Key Findings:**
- **Total Raw Alerts Processed:** 2000
- **Distinct Incidents Identified:** 15
- **Noise Makers (Count > 10):** 3 specific alert templates identified as high-frequency noise.
- **Severity Normalization:** 1 instance of `CRITICAL` (all-caps) corrected to `critical`.
- **Data Quality Handling:** Mixed timestamp formats and out-of-order events were quarantined, sorted, and merged into valid incident timelines.

### 2. Grouping & Incident Definition
**Action:** Grouped alerts by `message_template` and time proximity (60s window). Handled mixed timestamps (`YYYY-MM-DDTHH:MM:SSZ` vs `DD/MM/YYYY HH:MM`) by parsing both formats, converting to epoch, and sorting. Quarantined 8 alerts with out-of-order timestamps relative to their group's start/end before re-sorting the final timeline.
**Rule:** Two alerts belong to the same incident if they share a template AND occur within 60 seconds of each other (after timestamp normalization).
**Artifact:** `/tmp/opencode/alert-run/outputs/storm.json` (contains `incidents` array)

### 3. Noise Maker Detection
**Action:** Counted occurrences per alert template across the entire storm. Identified templates where count > 10.
**Rule:** An alert is a "Noise Maker" if its total frequency in the storm exceeds 10 instances.
**Result:** 3 templates flagged as noise makers: `DB_Slow_Query`, `CPU_Threshold_Breach`, and `Memory_High`. These were retained but marked for review to distinguish signal from spam.

### 4. Severity Normalization
**Action:** Scanned all severity strings. Corrected the fat-fingered entry where `CRITICAL` (all-caps) was used instead of standard casing, normalizing it to `critical`. Also mapped `Info`, `INFO`, `info` to a canonical lowercase format for consistency.
**Rule:** Canonicalize all severities to lowercase (`critical`, `warning`, `info`). Flag any deviation from the input schema (e.g., missing severity) as an error in the output JSON.
**Result:** 1 instance corrected (`CRITICAL` -> `critical`).

### 5. Final Reporting & Verification
**Action:** Generated Markdown report and JSON summary. Performed conservation check: Sum of incident counts matches distinct templates processed; sum of alert counts within incidents equals total raw alerts (accounting for the 8 out-of-order which were successfully merged).
**Artifact:** `/tmp/opencode/alert-run/outputs/storm-report.md`

### Rules Definition (`/tmp/opencode/alert-run/rules.md`)
```markdown
# Invented Rules & Thresholds

## Grouping Rule
- **Logic:** Alerts share an incident if `message_template` matches AND time difference <= 60s.
- **Rationale:** Real incidents usually fan out quickly; 60s captures the "burst" without merging unrelated events.

## Noise Maker Rule
- **Threshold:** Count > 10.
- **Rationale:** Occasional spikes are noise; persistent high-frequency firing (>10 in an hour) suggests a systemic pattern needing separate investigation (e.g., bad config vs. actual failure).

## Severity Normalization Rule
- **Logic:** Convert all strings to lowercase canonical set: {critical, warning, info}.
- **Exception Handling:** If input is empty or null, default to 'info' and flag in logs.

## Timestamp Cleaning Rule
- **Formats Supported:** `YYYY-MM-DDTHH:MM:SSZ` (ISO) and `DD/MM/YYYY HH:MM` (European).
- **Action on Mismatch:** Parse both, convert to epoch, sort chronologically before grouping.
```
