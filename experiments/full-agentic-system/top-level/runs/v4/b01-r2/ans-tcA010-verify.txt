# Queue Lag Report: Worker-2 Analysis & Artifact Generation

## 1. Workspace Layout & Decisions (`README.md`)

This workspace simulates production-grade analysis of a message queue with four consumers, partitioned topics, and lag snapshots over two days. The focus is on **Worker-2**, which exhibits bursty lag spikes correlated to three rebalance events.


### Decisions & Anomalies (`decisions.txt`)
| Mess Type | Handling Strategy | Rationale |
| :--- | :--- | :--- |
| **Missing Snapshots (20-min window)** | Excluded from rolling averages; flagged in `outputs/lag-report.md` with count. | Prevents skewing mean/max by non-existent data points. Explicitly documented for auditability. |
| **Backward Offsets** | Treated as negative delta; included in burst calculation but excluded from throughput estimate denominator. | Backward movement indicates reprocessing or error, not consumption rate. Including it would inflate "messages per minute" artificially. |

---

## 2. Rules & Thresholds (`rules.md`)

| Rule ID | Definition | Reasoning |
| :--- | :--- | :--- |
| **R-01** | **Burst Window**: Max lag over any 5-minute rolling window. | Captures sudden spikes better than simple mean; aligns with "bursty" behavior description. |
| **R-02** | **Rebalance Correlation Threshold**: Spike must occur within $\pm$ 30 seconds of a rebalance event to be correlated. | Prevents false positives where lag happens near but not caused by the event. |
| **R-03** | **Throughput Denominator**: Sum of positive offset deltas only. Excludes backward offsets. | Ensures throughput metric reflects actual consumption, not reprocessing loops. |
| **R-04** | **Precision**: No rounding below 2 decimal places for lag values (e.g., `145.23` ms). | Preserves "ugly precise number" requirement; avoids tidy lies. |
