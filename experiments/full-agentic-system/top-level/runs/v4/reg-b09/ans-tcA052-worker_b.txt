Phase 1 RULE SCAN:

- Rule: Naive route distance calculation triggers when order sequence is processed; total cells walked computed from sequential pick location movement. Trigger: Order processing begins (event: "order_start").
- Rule: Distance between two grid cells is calculated using Manhattan distance, enforced only if both cells are within bounds and not blocked. Trigger: Pick location accessed during naive routing.
- Rule: Blocked cell detection rule: if a path would pass through a blocked cell (defined as (row,col) in {(3,5), (7,2)}), the route must detour via adjacent valid cells; this rule expires after pathing is complete for that order. Trigger: Any movement attempt toward blocked cell during naive routing.
- Rule: When pick quantity is zero, the pick is marked as "skipped" and not counted in total distance or picked items; this state is returned to inventory. Trigger: Pick entry with quantity == 0 is read from input.
- Rule: When two picks share the same location (same row and column), they are merged into a single pick event, and the total quantity is summed; this rule applies only if both picks have valid quantities. Trigger: Two picks in same cell detected during order parsing.
- Rule: If a route would pass through a blocked cell during any heuristic pathing (nearest-neighbor or sector sweep), detour is enforced via shortest valid path around the block, and distance is recalculated. Trigger: Heuristic routing begins for any pick after order 17.
- Rule: Nearest-neighbor heuristic selects next pick based on minimum Manhattan distance to current location; this rule overrides naive ordering if a better path exists. Trigger: Heuristic routing starts (event: "heuristic_start").
- Rule: Sector sweep heuristic divides the grid into quadrants and picks are sorted by sector priority, then ordered within sectors; this rule is applied only after naive route fails to improve efficiency. Trigger: Heuristic routing begins with sector sweep method.
- Rule: Distance table per order is generated for both naive and improved routes, including all intermediate steps between pick locations. Trigger: After full pathing of each order in sequence.
- Rule: Total distance walked is computed as sum of Manhattan distances across all picks in a route; this rule expires after final route completion. Trigger: Final route completed (event: "route_complete").
- Rule: Percent saved is calculated as ((naive_distance - improved_distance) / naive_distance) * 100%, with denominator being the naive distance. Trigger: After both naive and improved routes are computed.
- Rule: If a pick location is invalid (row < 0 or row >= 12 or col < 0 or col >= 8), it is flagged as invalid, and the route is aborted for that order; this rule returns an error state. Trigger: Pick location parsed with out-of-bounds coordinates.
- Rule: When a pick has zero quantity, it is logged in defect log under "zero_quantity" category and not included in distance calculation. Trigger: Quantity field read as 0 during input parsing.
- Rule: If two picks are at the same cell but different items, they are merged into one entry with summed quantities; this rule applies only if both entries exist in the order set. Trigger: Duplicate location detected during order parsing.
- Rule: The final output JSON must contain only contract keys (e.g., "naive_distance", "improved_distance", "percent_saved", "distance_table") and no events, rules, or logs. Trigger: Final report generation step.
