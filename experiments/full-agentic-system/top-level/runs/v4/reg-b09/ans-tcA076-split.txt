(1) FIRST HALF SCOPE — rules and event lines belonging to the first half of the task (steps 1 through 3, inclusive):

- Load the tag dump file into a structured format (CSV or JSON), preserving each tag’s name, timestamp, and release date.  
- Parse each entry to extract: tag name, annotated date (as ISO 8601 string), and whether it is marked as a hotfix (based on pre-defined criteria).  
- For each tag in sequence, compute the gap-in-days to the previous release’s date; if no prior release exists, set gap to "N/A".  
- Assign a hotfix flag: any tag that appears outside the normal cadence window (e.g., more than 30 days after last release or before first) and is explicitly labeled as a hotfix in metadata OR has a commit count below threshold (defined by rule) shall be flagged.  
- If a tag references a commit not present in the dump, log it with full entry details and mark it as "missing-commit".  
- If a release date is ambiguous between tag time and announcement time, record both values and flag the ambiguity; resolve by default to tag time unless otherwise specified
