- On event: "archived" file loaded

  Rule: If a record is marked needs_review, flag for human review in review-needs-review.json. Trigger: status change during processing.

- On event: "status update to ok"  
  Rule: If a record returns to ok after quarantine → re-enable and add to active inventory; trigger update of total parts count. Trigger: status restoration.

- On event: "refill request triggered" (not in input)

- On event: "promotion applied"  
  Rule: If unit_cost is below $5.00 and part_category is consumable or sensor → promote to unit_cost = $5.0 in the final report. Trigger: post-deduplication, pre-report stage.

- On event: "fallback rule triggered"  
  Rule: If no valid data found for a part_id after deduplication → assign default values (category=fastener, quantity=1, unit_cost=$1.00) and log to fallback-defaults.json. Trigger: missing record in all input folders.

- On event: "source-ranking rule"  
  Rule: Rank parts by value per category; if multiple entries exist with same part_id → use the one from most recent file as source. Trigger: during manifest merge.

- On event: "expiry check triggered"  
  Rule: If last_inspected is older than 365 days (from today) → mark status to needs_review and log expiry notice in expired-items.json. Trigger: post-deduplication, pre-report stage.

- On event: "return request processed"  
  Rule: If a record has quantity >0 and return action occurs → reduce quantity by input amount; if quantity drops to zero → set status to defective. Trigger: outbound processing with return flag.

- On event: "revocation triggered"  
  Rule: If part_id is in quarantined or archived and revocation rule applies (e.g., part_name matches known bad pattern) → remove from active inventory and log revocation reason. Trigger: post-quarantine review.
