# Retry Storm Detection Pipeline

This repository implements an end-to-end retry storm detection system for a 50,000-record event log. All processing occurs in `/tmp/opencode/retry-run` with no external dependencies or network access.

## Purpose
Detect abnormal retry patterns (storm-adjacent and storm-core) in request logs based on defined rules. Outputs are deterministic, reproducible, and fully traceable to input rows.

## Data Shape
Each record has:
- `request_id`: string
- `timestamp`: ISO 8601 timestamp (string)
- `attempt`: integer ≥ 0
- `outcome`: one of "timeout", "5xx", "refused"

## Workflow Stages
1. Group records by request ID and compute attempt counts per logical request.
2. Flag storm-adjacent (>3 attempts) and storm-core (≥10 attempts).
3. Compute retry outcome distributions: timeout, 5xx, refused.
4. Identify storm windows: start, peak, drain for each storm-adjacent/storm-core group.
5. Surface all data warts: attempt=0, request ID reuse across logical requests.
