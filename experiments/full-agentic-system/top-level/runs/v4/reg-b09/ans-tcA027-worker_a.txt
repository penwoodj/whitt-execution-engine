Phase 1 RULE SCAN:

- Rule: Check presence and value of every variable in each environment (dev, staging, prod, sandbox) against expected matrix.  
  Trigger: On initial load of env files for any environment.  

- Rule: Flag variables that are absent in the documented expectation.  
  Trigger: When a variable is found missing from the documented expected matrix.  

- Rule: Flag variables that are present but have values differing from documented expectations (including trailing slash differences).  
  Trigger: On value comparison between actual and expected values after normalization.  

- Rule: Normalize whitespace and quoting in all env files before comparison.  
  Trigger: Before any diff operation; applied to every environment's env file.  

- Rule: Identify and list instances of trailing slash differences, including their exact lines and positions.  
  Trigger: When a value ends with a trailing slash and differs from the expected value (even if otherwise identical).  

- Rule: Flag duplicate variable definitions where the last definition wins; report which file defines it and its value.  
  Trigger: During parsing of each env file when multiple definitions exist for same variable.  

- Rule: Report blank lines in files as a mess instance, noting their position and context.  
  Trigger: On detection of blank lines within any environment's env file.  

- Rule: Flag inconsistencies in quoting (single vs double quotes) across files; report the actual quote type used.  
  Trigger: During parsing when variable values are enclosed in inconsistent quotation styles.  

- Rule: If a value differs only by trailing slash and caused an outage, flag it as dangerous and record historical context.  
  Trigger: When a trailing-slash difference is found and known to have caused a past outage (based on documented history).  

- Rule: On any contradiction between data and stated rules (e.g., if data shows a variable missing but rule says it should exist), report the contradiction with source file and line.  
  Trigger: During validation phase when actual data contradicts declared expectations or rules.  

- Rule: If no output artifact is produced for a stage, mark that stage as failed and log failure reason.  
  Trigger: When any stage produces nothing visible on disk (e.g., no envdrift.md, no json).  

- Rule: All outputs must be deterministic; if a script or function depends on randomness, seed it with current timestamp.  
  Trigger: At start of execution for all scripts involving file generation or comparison.  

- Rule: If any stage fails to run twice in sequence (first passes, second fails), report failure and log the difference.  
  Trigger: After running each stage twice; if second run differs from first, flag it as a state bug.  

- Rule: All logs must be one line per event with timestamp, showing what happened and when.  
  Trigger: At every stage execution (initial load, parsing, comparison, output).  

- Rule: If any rule is applied without clear threshold or justification, annotate the threshold and reason for it.  
  Trigger: When a rule feels arbitrary; must be documented in rules.md with rationale.  

- Rule: The final state on disk must allow a stranger to rerun the entire process from scratch.  
  Trigger: At end of all stages; if not possible, fail with error message.  

- Rule: Verification check must independently recompute and balance input → output flow (all inputs accounted for).  
  Trigger: After final output generation; verify no data is lost or added.  

- Rule: If a rule applies to a row but the actual data contradicts it, both the row and the rule must appear in output side by side.  
  Trigger: When a rule flags an inconsistency that is not present in raw data (or vice versa).  

- Rule: All percentages must include denominator; e.g., "12% of 50 variables" instead of just "12%".  
  Trigger: Whenever any percentage is reported in output.  

- Rule: Any caching or skipping step must be explicitly noted with reason and impact on reproducibility.  
  Trigger: When a step is skipped or cached for performance; must be documented.  

- Rule: All error messages must specify what failed, where it happened (file, line), and why.  
  Trigger: On any failure during execution of a stage.  

- Rule: If two stages can run in either order without effect, pick the one that produces earlier artifacts.  
  Trigger: When ordering is ambiguous; choose based on dependency flow.  

- Rule: Output must be plain text with tables only where needed and no buzzwords.  
  Trigger: At every stage output; avoid "optimized", "streamlined", etc.  

- Rule: All scripts must use standard library only (no external installs, no network).  
  Trigger: At script design phase; all tools must be built-in.  

- Rule: If a stage produces nothing visible on disk, it did not happen and must be reported as failed.  
  Trigger: After each stage completes; if no file is written or output exists, flag failure.  

- Rule: The workspace layout must be self-contained in /tmp/opencode/envdrift-run with clear README.md explaining structure.  
  Trigger: At initial setup of the workspace.  

- Rule: If a rule feels arbitrary, write threshold and reason next to it for future auditability.  
  Trigger: During rule design; if any rule lacks justification.  

- Rule: The final report must be pastable into chat without opening files.  
  Trigger: After all stages complete; output must be readable in plain text.  

- Rule: One line on what surprised you at the end of execution.  
  Trigger: At conclusion of entire process; only one such line.
