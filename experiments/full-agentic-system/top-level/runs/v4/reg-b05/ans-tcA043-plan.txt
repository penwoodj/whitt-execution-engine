# Bank Categorization Pipeline: Step-by-Step Plan

1. Create workspace directory structure at /tmp/opencode/bankcat-run with subdirectories:
   - raw/ for input data
   - derived/ for intermediate outputs
   - rules/ for rule definitions (rules.md)
   - logs/ for per-stage timestamps and errors
   - outputs/ for final deliverables

2. Seed random number generator to 42 for deterministic outcomes in all probabilistic or sampling steps.

3. Validate input data integrity: check that there are exactly 1200 rows, each with date, amount, description; log any deviation.

4. Parse raw CSV into structured format (list of dicts) using standard Python csv module; store as raw_parsed.jsonl in derived/parsed/.

5. Extract merchant names from descriptions via regex pattern matching: capture sequences like "Store #123", "Acme Co - Ref 789", or "Dining @ Pizza Hut" — use non-overlapping greedy matches with explicit delimiters.

6. Identify and log all instances of:
   - Store numbers embedded in description (e.g., "#123")
   - Reference codes (e.g., "Ref: ABC-456")
   - Date strings within descriptions
   - Duplicate merchant spellings (same entity, different phrasing)
   - Zero amount rows

7. Build a candidate category set from data via frequency analysis:
   - Count occurrences of each unique merchant name or phrase segment
   - Group similar phrases using Levenshtein distance threshold ≤ 2
   - Apply minimum frequency filter: only keep segments appearing ≥ 3 times
   - Final set size must be between 8 and 14; compute exact count from raw data

8. Generate rule list in rules.md with:
   - Category name
   - Regex pattern or string match logic (deterministic, no backtracking)
   - Threshold for matching (e.g., "must contain 'grocery' OR 'milk' AND not contain 'dining'")
   - Reason for threshold (e.g., "to avoid false positives from 'baked goods' in bakery")
   - Edge case examples with input and output

9. Apply each rule to every row in deterministic order:
   - For each row, test all rules in sequence
   - If a rule matches, assign category; if no match, go to unknown bucket
   - Flag any row where a rule applies but contradicts prior assignment (record both rule and row)

10. After rule application, validate that:
    - Unknown bucket contains ≤ 5% of total rows (i.e., ≤ 60 rows)
    - If >60, re-evaluate rules or thresholds; log in decisions.md
    - All rows are assigned a category or unknown

11. Compute monthly spend per category by:
   - Grouping transactions by month (YYYY-MM) from date field
   - Summing amounts per category per month
   - Output as monthly.json with full breakdown

12. Generate top 5 merchants overall by total amount spent, regardless of category.

13. Create categorized.csv with columns: date, amount, description, category, merchant_name (if available), flagged_mess_type (e.g., "has store #", "duplicate spelling")

14. Write categories.md listing all derived categories with:
    - Category name
    - Number of transactions assigned
    - Total spend in USD
    - Source phrases or patterns

15. Create verification script that:
    - Reads raw input file
    - Re-runs the full pipeline from scratch
    - Compares final output to current one
    - Checks for:
        - Same number of rows
        - Same category assignments per row
        - Same monthly spend totals
        - Same merchant counts and top 5 list
    - Outputs a conservation report with diffs if any

16. Run pipeline twice in sequence:
    - First run: produce initial outputs
    - Second run: re-run from raw input; compare results
    - If outputs differ, flag differences in logs/verify_diffs.md

17. Log each stage with one line per event:
    - Start time (ISO format)
    - End time (ISO format)
    - Duration (seconds)
    - Status (success/failure)
    - Error message if any

    - All strings are lowercased
