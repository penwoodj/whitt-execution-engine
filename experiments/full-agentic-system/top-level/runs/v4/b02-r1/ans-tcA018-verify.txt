# Rules Definition for Perf Regression Tracker

## R-01: Normalization Rule
**Action:** Calculate `best_time` = MIN(repeats), `median_time` = MEDIAN(repeats).
**Exception:** If repeat_count == 1, then best_time == median_time.
**Citation:** Used in C-03/S-Alpha analysis.

## R-02: Regression Detection Rule
**Action:** Flag scenario if `(current_best - prev_best) / prev_best > 0.10`.
**Precision:** Do not round percentages; output full float precision (e.g., 12.83%).
**Citation:** Used in C-04/S-Beta analysis (+12.83% flagged).

## R-03: Timestamp Ambiguity Rule
**Action:** If timestamps are identical, order commits by ID string sort.
**Citation:** Applied to C-02/C-03 pair ordering.

## R-04: Outlier Disposition Rule
**Action:** Identify spikes > 3 standard deviations or manual flags as outliers. Exclude from median calculation but retain in raw stats.
**Citation:** Applied to C-05/S-Gamma (spike handled).

## R-05: Pure Refactor Audit Rule
**Action:** If commit claims "pure refactor" but delta > 10%, override label to "Refactor with Regression".
**Citation:** Applied to C-04 audit failure.
