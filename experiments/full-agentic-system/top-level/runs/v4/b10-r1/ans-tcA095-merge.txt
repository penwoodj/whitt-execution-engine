Phase 1 RULE SCAN:

- Rule: Set stage timestamps for each card in backlog → doing → review → done. Trigger: Card arrival in backlog.  
- Rule: On entry to "doing", record start timestamp; on exit to "review", record end timestamp. Trigger: Card moves from backlog to doing.  
- Rule: On entry to "review", record start timestamp; on exit to "done", record end timestamp. Trigger: Card moves from doing to review.  
- Rule: On entry to "done", record final timestamp and mark as done. Trigger: Card moves from review to done.  
- Rule: If a card loops back from review to doing, increment loop count and extend dwell time in doing by the duration of the loop. Trigger: Card moves from review → doing (loop).  
- Rule: On any stage entry, if timestamp is before previous stage exit, flag as invalid and log error with row ID. Trigger: Any card transition where timestamp is retroactive.  
- Rule: If a card has done timestamp before its doing start timestamp, mark as invalid and record in error log. Trigger: Card has "done" before "doing".  
- Rule: On stage rename (e.g., "review" → "final review"), update all cards' stage names to reflect new name. Trigger: Stage name change detected in export.  
- Rule: For each card, compute per-stage dwell time as (exit timestamp - entry timestamp) for valid transitions. Trigger: Any valid transition between stages.  
- Rule: Compute total cycle time as (done timestamp - backlog entry timestamp). Trigger: Card reaches done stage.  
- Rule: Compute WIP over time by sampling daily and counting cards in each stage at that day. Trigger: Daily sampling of stage counts.  
- Rule: Flag any card with age > 14 days in a stage as "stuck". Trigger: Any card remains in a stage for more than 14 days.  
- Rule: For stuck list, record stage name, card ID, entry timestamp, and current age (days). Trigger: Card exceeds 14-day threshold in any stage.  
- Rule: On loop-back from review to doing, apply multipass accounting: add dwell time for each pass through doing. Trigger: Loop-back event detected.  
- Rule: If a stage has natural ordering dependency on the previous one (e.g., doing before review), enforce sequence and reject invalid transitions. Trigger: Transition attempt violates stage order.  
- Rule: When timestamps are timezone-naive, assume UTC unless explicitly marked with "utc" suffix. Trigger: Timestamp lacks timezone info.  
- Rule: For cards with done timestamp before doing start, treat as data contradiction and flag for manual review. Trigger: Done < Doing in any card.  
- Rule: If a stage name changes mid-export (e.g., "review" → "final review"), update all entries to new name and log rename event. Trigger: Stage name drift detected.  
- Rule: On invalid timestamp order, emit error with row ID and timestamps involved. Trigger: Any timestamp violation in transition sequence.  
- Rule: For cycle time distribution, compute median, P90, histogram from raw dwell times. Trigger: After all cards have valid cycle times.  
- Rule: For WIP over time, generate daily snapshots and detect spikes (≥2x baseline). Trigger: Daily sampling of stage counts.  
- Rule: If any card has a loop-back that exceeds 3 passes, flag as anomaly and record in logs. Trigger: Loop count ≥ 3.  
- Rule: When aging report flags stuck cards, only include those with age >14 days and valid entry timestamp. Trigger: Age threshold exceeded.  
- Rule: Final state must contain all original cards with updated stage names, timestamps, dwell times, cycle time, WIP counts, and stuck list. Trigger: End of processing pipeline.
