### PLAN FIRST (Steps & Formulas)

1.  **Setup Workspace**: Create `/tmp/opencode/subs-run` with subfolders `raw`, `parsed`, `repaired`, `reports`, `logs`, `rules`.
2.  **Generate Test Data**: Write a Python script to create `input.srt` containing: 800 cues, overlaps, >5s gaps, <0.5s durations, numbering gaps, mixed timestamp delimiters (`,` and `.`), out-of-order timestamps, and multi-line speaker labels.
3.  **Strict Parser (`parse_srt.py`)**: Read `input.srt`; tokenize lines; validate index continuity; extract start/end times handling both delimiters; flag malformed cues in a list without crashing; output to `parsed/`.
4.  **Defect Analyzer (`analyze_defects.py`)**: Load parsed data; calculate overlaps, gaps, short durations, word-per-second (WPS) rates; identify out-of-order timestamps and label anomalies; generate defect counts for the "Human Table".
5.  **Repair Engine (`repair_srt.py`)**: 
    *   Sort cues by start time (handling out-of-order).
    *   Resolve overlaps: Trim end of later cue to match start of earlier cue.
    *   Resolve gaps >5s: Report only, do not fill.
    *   Extend short durations (<0.5s): Add 0.1s to duration, adjust end time.
    *   Renumber indices sequentially starting at 1.
    *   Output repaired `repaired.srt`.
6.  **Reading Speed Pass (`speed_check.py`)**: Calculate WPS for all cues; identify cues >21 chars/sec (using average word length approx or raw char count if words not distinct, assuming "characters per second" implies visual density); split long cues or extend duration to meet threshold; log changes.
7.  **Defect Comparison (`compare_defects.py`)**: Run defect analyzer on repaired data; generate table comparing Pre- vs Post- counts (Overlaps, Gaps, Short Durations, High WPS).
8.  **Report Generator (`generate_reports.py`)**: Create `repair-report.md` with Human Tables and JSON blocks; create `defects.json`; ensure numbers match exactly between Markdown and JSON.
9.  **Rules Documentation**: Write `rules.md`, `decisions.md`, and `readme.md`.
10. **Verification Script (`verify.py`)**: Independently re-parse `repaired.srt`; re-calculate all metrics; compare against `defects.json` and `repair-report.md`; exit non-zero if any drift found.
11. **Execution & Timing**: Run pipeline with timestamps logged to `logs/`; capture real wall-clock times for each stage.
12. **Double-Run Test**: Execute full pipeline twice; verify state consistency (idempotency).
