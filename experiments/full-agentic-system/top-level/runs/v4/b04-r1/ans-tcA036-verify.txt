### 2. Rules & Thresholds (`rules.md`)

```text
# SRT Repair Rules

1. PARSING:
   - Malformed cues (missing timestamp, bad numbering) are flagged but not skipped.
   - Timestamp format must be HH:MM:SS,mmm or HH:MM:SS.mmm. Mixed formats trigger a warning log entry.

2. TIMING FIXES:
   - Overlaps: Trim the start of the second cue to match the end of the first.
   - Gaps > 5s: Report in `defects.json` but do not auto-fill (per user constraint).
   - Short Durations (<0.5s): Extend duration by adding text or padding time until >= 0.5s.

3. READING SPEED:
   - Threshold: 21 characters per second (including spaces).
   - Action: Split cue if word count / duration > 21. New split point calculated to reduce speed below threshold.

4. OUTPUT FORMAT:
   - Human Table: Markdown with columns [Cue, Start, End, Duration, Status].
   - Machine JSON: Array of objects with keys `cue_id`, `start_ms`, `end_ms`, `duration_ms`, `action`.
   - Consistency Check: Sum of durations in both files must match exactly.

5. ERROR LOGGING:
   - Format: "Stage X: Rule Y failed at Cue Z because [reason]."
   - Contradictions: If data contradicts rules (e.g., user says 'no gaps' but gap exists), log contradiction explicitly.
```
