Phase 1 RULE SCAN:

- Daily backup rule: A new daily backup is created every day at midnight, with a size drawn from [100MB, 250MB] uniformly, corruption chance set to 1% per snapshot. Triggered by: daily event (every day).
- Weekly promotion rule: On the first day of each week, all daily backups from the prior week are promoted to weekly tier if they are at least 7 days old and have not been corrupted. Triggered by: weekly day (day 0 of week).
- Monthly promotion rule: On the first day of each month, all weekly backups from the prior month are promoted to monthly tier if they are at least 4 weeks old and have not been corrupted. Triggered by: monthly day (day -1 of month).
- Grandfather-father-son rotation rule: A snapshot is retained only if it satisfies the grandfather-father-son hierarchy: daily backups are kept for 7 days, weekly backups for 4 weeks, monthly backups for 12 months. If a backup fails to meet tier retention, it is removed from that tier and falls back to the previous tier (e.g., a corrupted daily backup is dropped; if no prior tier exists, it is discarded). Triggered by: every day during rotation check.
- Corrupted snapshot fallback rule: When a retained snapshot corrupts (1% chance per snapshot), the policy falls back to the most recent valid snapshot in the previous tier (e.g., a corrupted weekly backup falls back to the last valid daily backup from the same week). If no such snapshot exists, the system logs an error and marks the retention as failed. Triggered by: corruption event (1% per snapshot).
- Restore-drill eligibility rule: A restore drill is triggered randomly every 30 days; it requires a snapshot that was eligible for retention at the time of the drill request. If no such snapshot exists, the drill fails and is logged with the reason "no eligible snapshot". Triggered by: random drill event (every 30 days).
- Deletion rule: At the end of each month, all monthly backups older than 12 months are deleted. Triggered by: end-of-month day.
- Promotion ambiguity resolution rule: When a weekly and monthly backup fall on the same day (e.g., day 1 of January), the weekly backup is promoted first, then the monthly backup. This ensures no overlap in promotion timing. Triggered by: overlapping day event (same day for both week and month).
- Backup size override rule: If a daily backup is scheduled during a holiday (defined as Jan 1, July 4, Nov 11), its size is set to 500MB instead of the default. Triggered by: holiday day.
- Restore-drill pass rate rule: A restore drill passes only if the requested snapshot exists and has not been corrupted. If it fails due to non-existence or corruption, the event is logged with details. Triggered by: each restore drill request.
