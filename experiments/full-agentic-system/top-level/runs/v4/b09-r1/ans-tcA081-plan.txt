## Rules Applied (rules.md)

### Install-without-clean detection rule  
**Threshold**: Any layer with command containing `apt-get install` or `yum install` **and no subsequent command** that removes the package or its cache.  
**Reason**: These installs add large files to the filesystem without cleanup, and are a classic source of bloat. If a layer has such an install but no removal (e.g., `rm -rf /var/lib/apt/lists`) in any later layer, it is flagged.

### Duplicated data adds rule  
**Threshold**: A layer with command that copies or installs a file **that appears identically** in another layer earlier than it.  
**Reason**: If the same file is added twice (e.g., via `COPY`), and no prior layer removed it, this wastes space. We flag such cases even if not explicitly named.

### Secrets-in-layer rule  
**Threshold**: Any command or file content that contains a string like "password", "secret", "key", "token" in any text.  
**Reason**: These are red flags for security and may indicate accidental inclusion of sensitive data, which is both wasteful (if stored) and dangerous.

### Cumulative size correction rule  
**Threshold**: Two entries where `size` field is cumulative (i.e., layer N's size = sum of all prior layers).  
**Reason**: The raw dump incorrectly treats sizes as cumulative. We must correct this by computing actual layer-by-layer size from the raw data, using a rolling sum.  
- **Correction method**: For each layer, `layer_size = cumulative_size - previous_cumulative_size` (with first layer being `cumulative_size`).  
- **Log entry**: "Corrected 2 entries where cumulative size was misreported."

### Zero-size layer handling rule  
**Threshold**: A layer with `size == 0`, but command contains metadata-only actions like `RUN echo 'metadata' > /etc/metadata`.  
**Reason**: These layers do not add files, but they are still part of the image history and must be counted in bloat analysis. We include them as "present" and flag their purpose.
