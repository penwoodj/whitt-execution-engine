Phase 1 RULE SCAN:

- Rule: Gap duration distribution per station computed at row level; triggers on every temperature row with missing data.  
  Event/Claim: Any row with a gap (missing field) in any column of any station.  

- Rule: Total missing percentage per station calculated as (total missing days / total days in year) × 100%; triggers after all gaps are identified and categorized by station.  
  Event/Claim: After full gap census is completed for each station.  

- Rule: Time-interpolation applied to gaps under 3 consecutive days; triggers on any gap duration < 3 days, across any field, at any station.  
  Threshold: 3 days (inclusive of start/end day); reason: short gaps can be reasonably estimated via linear interpolation between adjacent valid days using time-based neighbor data.  

- Rule: Station-correlation fill applied to gaps ≥ 3 days; triggers on gap duration ≥ 3 days and when no time neighbors exist or are insufficiently reliable.  
  Threshold: 3 days (inclusive); reason: longer gaps require cross-station consistency checks due to temporal instability, and station correlation provides better physical plausibility than pure time interpolation.  

- Rule: Interpolation method flagged per row with a "method" column; triggers on every row that undergoes any form of gap fill (time or station-correlation).  
  Event/Claim: After application of either time-interpolation or station-correlation to a row.  

- Rule: Freeze event detection based on raw data; triggers on each day where temperature ≤ 0°C in any station, using original units and values.  
  Event/Claim: On every daily row with valid temperature data (before any interpolation).  

- Rule: Freeze event detection after gap fill; triggers on each day where interpolated or filled temperature ≤ 0°C in any station.  
  Event/Claim: After all gaps are filled and data is updated to interpolated values.  

- Rule: Physical outlier detection for impossible temperatures; triggers when a temperature value is below -40°C (or below freezing point of water) regardless of unit, even if not missing.  
  Threshold: Temperature < -40°C in any station; reason: physical impossibility of such readings in standard weather sensors.  

- Rule: Unit conversion applied to Celsius and Fahrenheit data; triggers when a station reports temperature in non-Celsius units (Fahrenheit).  
  Event/Claim: When a station is identified as reporting in Fahrenheit, conversion to Celsius occurs using formula: C = (F - 32) × 5/9.  

- Rule: Clock skew detection and correction; triggers on rows where timestamp differs from expected day-of-year sequence by more than 1 hour or when adjacent days are out of order.  
  Threshold: Absolute difference in timestamps > 1 hour, or day-of-year jump > 1; reason: indicates sensor drift or data logging error.  

- Rule: Gap fill fallback to station correlation if time interpolation fails due to insufficient neighbor data; triggers when time-interpolation is attempted but no valid adjacent days exist.  
  Event/Claim: During time-interpolation attempt, if fewer than two valid neighboring days are available at any station.  

- Rule: Source-ranking rule: prefer cross-station consistency over time-based interpolation for gaps ≥3 days; triggers on gap duration ≥3 days and when multiple stations have data in same period.  
  Event/Claim: When a gap exists and at least one other station has valid temperature readings during the missing interval.  

- Rule: Return of missing data after fill policy applies; triggers only if original row had no data, and interpolation or correlation fills it — no return rule otherwise.  
  Event/Claim: After successful application of any gap-fill method to a previously missing field.
