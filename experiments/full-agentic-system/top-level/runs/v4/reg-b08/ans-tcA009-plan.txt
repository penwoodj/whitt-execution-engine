1. Load all 300 JSON traces from `/tmp/opencode/trace-run/traces/*.json` into memory as a list of Python dictionaries; validate each trace has a root span named `serve.request`, and log any missing or malformed traces with full path and error message.

2. For each span in every trace, extract name, start_microsecond, duration, status, and parent_id (if present), then compute per-span-name average self-time (excluding children) using only spans that are not descendants of others — define "self time" as `duration` minus the sum of child durations; exclude any span with negative duration or invalid timestamps.

3. For each trace, compute total duration (end_microsecond - start_microsecond of root), then identify the three traces with highest total duration and extract their full span trees in order from root to leaf, preserving exact microsecond values and nesting structure.

4. Aggregate all spans by name across all traces; for each span name, count how many times it appears in a failed status (status == "ERROR" or "FAILED"), then compute the percentage of total span occurrences that fail — include denominator (total span count) next to each percentage.

5. Compute the overall slowest span name globally (by sum of self-time), and calculate its share of total self-time across all spans, with full precision; output both the name and the exact fraction of total time it consumes, including denominator.

6. Generate a human-readable waterfall report (`outputs/waterfall.md`) as an indented list for each of the three longest traces, showing span names, start and end times (in microseconds), and duration, with no rounding — preserve all raw numbers from input.

7. Generate a machine-readable JSON version of the same waterfall structure (`outputs/waterfall.json`), structured as a list of trace waterfalls, each being an array of spans with fields: name, start_microsecond, end_microsecond (calculated), duration, status, parent_id.

8. Write a `rules.md` file at root explaining every rule used in steps 2–5, including thresholds (e.g., "negative duration = invalid", "parent_id must be valid"), why they were chosen, and any arbitrary decisions with justification.

   - The slowest span name and its time share match global totals
   - Failure rate percentages are correct with full denominators

   - All invalid spans (negative durations, illegal parent-child) are flagged and reported
