# Phase 1 RULE SCAN

This phase lists every rule defined in the task that changes state during the processing event or claim list (i.e., when a build record is processed), including any expiry, return, revocation, refill, promotion, fallback, source-ranking rule, and handling of duplicates/missing fields. Each line marks which event triggers it.

1.  **Rule: Pass Rate Calculation** – Triggered by every valid build record; computes pass count / total tests for that build.
2.  **Rule: Suspicion Flagging (5-95%)** – Triggered if a test's overall pass rate falls strictly between 0.05 and 0.95; marks the test as "suspicious".
3.  **Rule: Failure Cluster Detection** – Triggered for suspicious tests; scans consecutive runs or same-day bunching to identify clusters of failures.
4.  **Rule: Correlation Check (Pearson)** – Triggered on pairs of suspicious tests; calculates precise Pearson correlation coefficient without rounding.
5.  **Rule: Confidence Scoring** – Triggered per flagged test; assigns a confidence note based on cluster density and correlation strength.
6.  **Rule: Duplicate Record Handling** – Triggered when two records share the same build ID but have different IDs or vice versa; logs both rows with a "duplicate" flag.
7.  **Rule: Missing Field Fallback** – Triggered when a build record has missing test fields entirely; assigns default values (0 passes, 0 total) and flags as "missing_data".
8.  **Rule: Stage Timing Logging** – Triggered at the start/end of each processing stage; records wall-clock timestamps for timing tables.
9.  **Rule: Output Consistency Check** – Triggered after generation; verifies `flake.json` numbers match `flakes.md` text representation exactly.
10. **Rule: Verifier Invariant Enforcement** – Triggered by the separate verifier script; checks that all computed values are reproducible and invariants (e.g., pass rate bounds) hold.
