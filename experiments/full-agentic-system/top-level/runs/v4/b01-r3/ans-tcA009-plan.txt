### PLAN FIRST: Steps & Formulas/Rules

1.  **Initialize Workspace**: Create `/tmp/opencode/trace-run` with subdirectories `scripts`, `outputs/raw`, `outputs/report`, `logs`. Write `rules.md` defining precision (no rounding), error handling, and artifact requirements.
2.  **Ingest Data**: Read all JSON trace files from a simulated source or provided location into `outputs/raw/traces/`. Log count of traces loaded. Handle the single orphan span by flagging it in metadata but including it in calculations where possible.
3.  **Validate & Clean (Stage 0)**: Iterate every span. Flag illegal overlaps (child start < parent start) and negative durations. Store these flags in a `validation_issues.json` alongside raw data; do not drop them silently. Log count of issues found.
4.  **Compute Self-Times (Step 1)**: For each unique span name, sum total duration excluding children's time. Formula: $T_{self} = T_{total} - \sum T_{children}$. Calculate average and p99 per name. Handle orphan spans by treating their duration as self-time if no parent exists. Output `step1_self_times.csv` (human) and `step1_self_times.json` (machine).
5.  **Identify Slowest Span (Step 2)**: Find the span name with maximum $T_{self}$. Calculate percentage of total trace time burned: $(T_{slowest\_span\_total} / T_{trace\_root}) \times 100$. Output `step2_slowest_span.txt`.
6.  **Find Deepest Traces (Step 3)**: Sort traces by root span duration descending. Select top 3. Generate indented waterfall lists for each, preserving microsecond precision. Output `step3_deep_waterfalls.txt` and `step3_deep_waterfalls.json`.
7.  **Status Breakdown (Step 4)**: Group spans by name, then count status codes (OK/ERROR). Calculate failure rate per name: $(Count_{error} / Count_{total}) \times 100$. Output `step4_status_breakdown.csv` and `step4_status_breakdown.json`.
8.  **Generate Waterfall Report (Step 5)**: Combine Step 3 data into a formatted Markdown file (`waterfall.md`) with the JSON payload (`waterfall.json`). Ensure both files contain identical numerical values.
9.  **Create Rules & README**: Write `README.md` documenting workspace layout, stage order decisions, and artifact paths. Include specific thresholds (e.g., "p99 calculated via linear interpolation").
10. **Run Verification Script**: Execute an independent Python script that re-reads raw JSON files, recomputes all metrics from scratch using the same logic, and compares results against `outputs/report/*.json`. Flag any drift > 0. Log exit code (0 for pass, non-zero for fail).
11. **Final Report Assembly**: Generate `final_report.md` containing: Human-readable summary tables at top, Machine JSON blocks below each table, timing logs per stage, list of validation issues found in Step 3, and paths to all artifacts.
12. **Idempotency Check**: Run the entire pipeline a second time immediately after the first run completes successfully. Verify that output files are identical (byte-for-byte) or cleaned/re-generated correctly without state corruption. Log "Second run completed" only if checksums match.
