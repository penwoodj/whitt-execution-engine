### PLAN FIRST: Steps & Formulas/Rules

1.  **Initialize Workspace**: Create `/tmp/opencode/queue-run` with subdirectories `scripts`, `outputs`, and root files (`rules.md`, `decisions.log`, `readme.md`).
2.  **Generate Synthetic Data Script (`gen_data.sh`)**: Produce raw CSVs for `offset_snapshots.csv` (timestamps, consumer_id, partition_id, log_end_offset, committed_offset) including missing windows, backward offsets, and specific bursts for `worker-2`. Include `rebalance_events.csv` with 3 timestamps.
3.  **Define Rules (`rules.md`)**: Document thresholds for "lag burst" (>50% increase), "stuck consumer" (avg lag > mean of others * 1.5), and data quality handling (missing rows, negative deltas).
4.  **Lag Calculation Script (`calc_lag.sh`)**: Compute `lag = log_end_offset - committed_offset`. Calculate rolling max/mean per partition/consumer. Flag rows where offsets go backward or snapshots are missing. Output to `outputs/lag_per_consumer_partition.csv`.
5.  **Throughput Estimation Script (`calc_throughput.sh`)**: Calculate offset deltas between consecutive snapshots for each consumer/partition pair. Compute messages per minute (mpm). Handle division by zero if timestamps are identical. Output to `outputs/throughput_estimates.csv`.
6.  **Correlation Analysis Script (`correlate_rebalance.sh`)**: Join lag data with rebalance events. Identify lag spikes occurring within $\pm$ 1 minute of a rebalance timestamp. Distinguish between "recovery after rebalance" and "spike unrelated to rebalance". Output to `outputs/rebalance_correlation.csv`.
7.  **Verdict Logic Script (`determine_verdict.sh`)**: Compare worker-2's average lag against the global mean lag of all consumers. If worker-2 avg > global_mean * 1.5 AND no single partition explains >80% of its total lag, classify as "Slow Consumer". Else if one partition dominates, classify as "Stuck on Hot Partition". Output to `outputs/verdict.txt`.
8.  **Data Quality Audit Script (`audit_quality.sh`)**: Scan raw data for missing time windows and backward offset jumps. Log each instance with a unique ID in `decisions.log`.
9.  **Report Generation Script (`generate_report.sh`)**: Aggregate all CSVs into `lag-report.md` (tables, methodology) and `lag.json` (structured metrics). Include the one-paragraph honest methodology note.
10. **Verification Script (`verify_run.sh`)**: Independently recompute key metrics from raw data using separate logic. Compare field-by-field against generated outputs. Exit non-zero on any drift. Output verification report to `outputs/verification_report.txt`.
11. **Final Execution & Timing**: Run the pipeline, capture timestamps for each stage into a log, and generate the final summary table.
