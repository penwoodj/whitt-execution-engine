### Phase 1 RULE SCAN (First Half Only)

This phase identifies the logical rules governing the state changes for the "First Half" of the task (Extraction and Resolution). The subsequent phases (Anchor Check, Move Guessing, File Generation) are ignored per the worker A instruction.

1. **Rule: Link Extraction & Edge Case Capture**
   - *Trigger:* Scanning all 60 markdown files in `/tmp/opencode/linkrot-run/docs`.
   - *State Change:* Creates a raw list of `{source_file, target, anchor}` tuples.
   - *Edge Handling:* Captures unencoded spaces (treated as literal string mismatch), symlink loops (flagged as `error:loop`), and identical filenames in different folders (resolved via relative path context).

2. **Rule: Relative Target Resolution**
   - *Trigger:* Processing each extracted link tuple against the actual file tree structure.
   - *State Change:* Assigns status `live`, `dead`, or `moved-guessable`.
   - *Logic:*
     - `live`: File exists at resolved path.
     - `dead`: Resolved path does not exist (404/missing).
     - `moved-guessable`: File missing, but filename matches a file in another directory (requires Stage 3 logic to confirm, so initially marked `moved-guessable` pending verification).

3. **Rule: Anchor Existence Check**
   - *Trigger:* For links where the target file is found (`live`).
   - *State Change:* Validates if the specific anchor text exists in the target heading list.
   - *Logic:* Returns `valid_anchor`, `invalid_anchor` (heading missing), or `partial_match` (if fuzzy matching rules were applied, though strict equality is default).

4. **Rule: Move Guessing Proposal**
   - *Trigger:* For links marked `moved-guessable`.
   - *State Change:* Proposes a corrected path by searching the filename in other directories.
   - *Logic:* If found, updates status to `live` with new path; if not found, reverts to `dead` or keeps as `moved-unknown`.

5. **Rule: Error Message Specificity**
   - *Trigger:* Any failure during extraction or resolution.
   - *State Change:* Generates error string containing `{file_path, specific_failure_reason}` (e.g., "Space unencoded in target", "Symlink loop detected").

6. **Rule: Output Format Duality**
   - *Trigger:* Generation of any report stage.
   - *State Change:* Ensures parallel generation of `Human Table` and `Machine Copy` with identical data to prevent drift.

7. **Rule: Denominator Requirement for Percentages**
   - *Trigger:* Any statistical calculation within the output (e.g., "12%").
   - *State Change:* Appends `{denominator}` to the string representation (e.g., "12% of 60 files").

8. **Rule: Timestamping & Timing Logs**
   - *Trigger:* Completion of any processing stage.
   - *State Change:* Records `{stage_name, start_time, end_time, duration_ms}` in a dedicated log table.

9. **Rule: Verification Logic (Independent Check)**
   - *Trigger:* Post-processing validation phase.
   - *State Change:* Recomputes counts from raw data; if `computed != reported`, flags `error:drift`.
