# Decisions Log (`decisions.md`)

**1. Repeat Normalization Strategy:**
*   **Rule:** For each scenario per commit, calculate `best` (minimum time) and `median`. Use these for delta calculations to reduce noise from single outliers while preserving the "typical" performance floor.
*   **Rationale:** The prompt specifies 3 repeats but notes one scenario has only 1 repeat. Using median on N=1 is identity; using best on N=1 is also identity. For N>=2, this filters spikes.

**2. Delta Calculation & Thresholding:**
*   **Rule:** Calculate Commit-over-Commit delta as `(Current_Best - Previous_Best) / |Previous_Best| * 100`. Flag if `delta > 10%` (regression).
*   **Rationale:** Matches prompt requirement ("slowing more than 10 percent"). Denominator uses absolute value to handle potential negative deltas correctly in percentage math.

**3. Audit Contradiction Handling:**
*   **Rule:** If a commit claims "pure_refactor" but delta != 0 (or specifically if delta is significant), flag as `AUDIT_CONTRADICTION`.
*   **Rationale:** Data wins over claim. A refactor should ideally be neutral; any slowdown implies code change or regression, contradicting the claim.

**4. Timestamp Ambiguity Resolution:**
*   **Rule:** If two commits share a timestamp (ambiguous order), assume lexicographical sort of Commit ID as tie-breaker for ordering in delta calculation.
*   **Rationale:** Prevents division by zero or undefined behavior when calculating deltas between identical timestamps.

**5. Outlier/Noise Disposition:**
*   **Rule:** Visible spikes are included in `best` calculation but noted in logs. No row is dropped silently unless explicitly rejected via rule (e.g., N=1 with no repeats).
*   **Rationale:** "Surfaced not absorbed."

**6. Output Format:**
*   **Rule:** Human-readable Markdown tables for all stages. Machine-readable JSON (`perf.json`) mirroring exact numeric values from Markdown tables.
*   **Rationale:** Ensures verifier can recompute and compare field-by-field without drift.
