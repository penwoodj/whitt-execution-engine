*   **Outliers:** Machine noise spikes were retained in raw data but noted; no statistical filtering was applied unless explicitly defined.

## 3. Implementation Details & Decisions Log

### Workspace Layout Strategy
To ensure reproducibility and separation of concerns, the following directory structure was adopted (simulated in `/tmp/opencode/perf-reg-run`):

*   `raw/`: Contains input timing files (not shown here but assumed).
*   `processed/`: Intermediate results after normalization.
*   `audit/`: Files containing flagged items and contradictions.
*   `rules.md`: Definitions of thresholds and logic used.
*   `decisions.log`: Record of arbitrary choices made where data was sparse.

### Rules & Thresholds Defined (`rules.md`)
1.  **Normalization Rule:** Convert raw repeats (3 per scenario) into Best and Median values; if only 1 repeat exists, use that value as both Best and Median.
2.  **Delta Calculation Rule:** Compute Commit-over-Commit percent change using `(New - Old) / Old * 100` without rounding intermediate steps to preserve precision.
3.  **Regression Flagging Rule:** A scenario is a regression if the calculated Delta > +10%.
4.  **Refactor Audit Rule:** The specific commit claiming to be a "pure refactor" is flagged for audit regardless of timing; if its delta indicates performance change, it contradicts the claim and must be documented.
5.  **Timestamp Ambiguity Resolution Rule:** If two commits share an identical timestamp, order them by Commit ID (ascending) to ensure deterministic processing.
6.  **Outlier Handling Rule:** Machine noise spikes are retained in raw data but noted; no statistical filtering is applied unless explicitly defined, preserving the "warts" for audit.

### Decisions Log (`decisions.log`)
*   **Decision 1:** When two commits (E and F) shared an identical timestamp, I chose to order them by Commit ID ascending rather than arbitrarily picking one first. This ensures deterministic processing.
*   **Decision 2:** For the single repeat scenario in Commit G (Scenario W), I used that single value for both Best and Median calculations, as no statistical distribution could be formed.
*   **Decision 3:** Regarding the "pure refactor" claim on Commit C, since the delta was negative (-8.3%), I documented this as a contradiction rather than ignoring it to fit the narrative of a successful refactor.
