### PLAN FIRST: Steps with Formulas/Rules

1.  **Initialize Workspace & Rules**: Create directory structure (`/tmp/opencode/trace-run`), write `rules.md`, `README.md`, and logging setup scripts.
2.  **Load Raw Data**: Read all JSON trace files from the workspace root into memory, validating schema (span name, start_us, duration, status).
3.  **Handle Data Warts**: Identify and flag illegal overlaps (child start < parent start), negative durations, and orphan spans; record counts in `data_warts.log`.
4.  **Compute Self-Times (Stage 1)**: For each span name, calculate average self-time = $\frac{\sum (\text{duration} - \sum \text{children\_durations})}{\text{count}}$ excluding children time; output to `outputs/self_times.csv` and `outputs/self_times.json`.
5.  **Identify Top Traces (Stage 2)**: Sort traces by total duration descending; select top 3; generate indented waterfall lists preserving microsecond precision; output to `outputs/top_waterfalls.txt` and `outputs/top_waterfalls.json`.
6.  **Find Global Slow Span (Stage 3)**: Identify span name with highest absolute self-time contribution across all traces; calculate percentage of total system time = $\frac{\text{total\_self\_time}}{\sum \text{all\_trace\_durations}}$; output to `outputs/slowest_span.txt` and `outputs/slowest_span.json`.
7.  **Status Breakdown (Stage 4)**: Aggregate span name vs status counts; calculate failure rate per name = $\frac{\text{count(status='ERROR')}}{\text{total\_count}}$; output to `outputs/status_breakdown.csv` and `outputs/status_breakdown.json`.
8.  **Generate Waterfall Report (Stage 5)**: Combine top waterfalls into a formatted Markdown report (`waterfall.md`) with a raw JSON companion (`waterfall.json`); ensure human-readable tables above machine data.
9.  **Create Verifier Script**: Write `verify.sh` that re-computes all metrics from raw JSON files using independent logic (no pipeline state), compares against outputs, and exits non-zero on mismatch.
10. **Execute Pipeline & Logging**: Run the main analysis script (`run.sh`) with timestamps logged to `logs/stage_*.log`; ensure idempotency by cleaning previous outputs first.
11. **Run Twice Test**: Execute pipeline twice; compare checksums of all output files between runs to detect state bugs or non-determinism.
12. **Generate Final Report**: Create `REPORT.md` summarizing paths, run times (from logs), key findings, and data wart handling notes.
13. **Hostile Verification Run**: Execute `verify.sh`; if it passes, log success; if it fails, append error details to `logs/verification_errors.log`.
