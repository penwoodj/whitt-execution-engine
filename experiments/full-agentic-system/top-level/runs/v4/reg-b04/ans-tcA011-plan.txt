### PLAN FIRST (Steps & Formulas)

1.  **Initialize Workspace**: Create `/tmp/opencode/retry-run` directory structure (`raw/`, `processed/`, `reports/`, `scripts/`, `logs/`) and generate synthetic data file `raw/log.csv` with 50,000 records including edge cases (reused IDs, attempt=0).
2.  **Stage 1: Aggregation & Storm Classification**: Group by `request_id`; count attempts per ID; flag `storm_adjacent` (>3 attempts) and `storm_core` (>10 attempts); calculate timestamps for start/peak/drain windows using first/median/last attempt timestamps.
3.  **Stage 2: Outcome Analysis**: Filter retry records (attempt > 1); group by outcome code; count totals and percentages with explicit denominators.
4.  **Stage 3: Edge Case Audit**: Identify rows where `request_id` reuses a previous logical request or `attempt=0`; log these in a dedicated audit table with the specific rule applied to handle them.
5.  **Stage 4: Report Generation (Human)**: Generate `reports/storm.md` containing summary tables for Storm Distribution, Outcome Dominance, and Edge Cases; ensure plain text formatting.
6.  **Stage 5: Machine Copy Generation**: Generate `reports/storm.json` with identical numerical values to the markdown report but in JSON format for parsing.
7.  **Stage 6: Verifier Script Execution**: Run independent Python script that re-reads `raw/log.csv`, recomputes all metrics, and compares against `storm.md` and `storm.json`; output strict diff or pass/fail status.
8.  **Stage 7: Timing & Logging**: Record wall-clock time for each stage; append one-line logs to `logs/stage_logs.txt`; generate final timing table in `reports/timing_table.csv`.
9.  **Stage 8: Final Verification Loop**: Execute the full pipeline a second time (fresh state) and run the verifier again to ensure deterministic reproducibility.
10. **Stage 9: Documentation Assembly**: Create `README.md` describing workspace layout, rules used, and how to reproduce; include `rules.md` with all thresholds and rationales.
