### Phase 1: RULE SCAN

The following rules govern state changes during the event processing (grouping, normalization, noise detection). Each rule is listed with its trigger condition.

1.  **Grouping Rule**: Alerts are merged into a single incident if they share the same `message_template` AND their timestamps fall within a configurable time window (default: 5 minutes) relative to the first occurrence of that template.
    *   *Trigger*: Arrival of an alert with matching template and timestamp proximity.
2.  **Timestamp Normalization Rule**: Timestamps in ISO-8601 format (`YYYY-MM-DDTHH:MM:SS`) are converted to a canonical epoch integer; timestamps in Unix Epoch seconds are left as-is but validated for range (e.g., > 0).
    *   *Trigger*: Arrival of an alert with non-canonical timestamp format.
3.  **Out-of-Order Handling Rule**: If an alert's normalized timestamp is earlier than the current incident's start time, it is re-inserted into the incident timeline and the incident span is recalculated.
    *   *Trigger*: Arrival of an alert where `alert_ts < incident_start_ts`.
4.  **Severity Normalization Rule**: Severity strings are lowercased; specific typo mappings (e.g., "CRITICAL" -> "critical") are applied to standardize severity levels for grouping logic if configured, though here they remain distinct values unless explicitly merged by a higher-level rule. *Correction based on task*: The task implies normalization includes fixing the "fat-fingered CRITICAL". Rule: If `severity` == "CRITICAL", map to "critical" (lowercase) for consistency in reporting, but retain original value in raw log if required.
    *   *Trigger*: Arrival of an alert with severity "CRITICAL".
5.  **Noise Maker Detection Rule**: An incident is flagged as a "noise maker" if the count of alerts within it exceeds `10`.
    *   *Trigger*: Completion of grouping for an incident where `len(alerts) > 10`.
6.  **Quarantine Rule**: Alerts with invalid timestamps (e.g., negative epoch, malformed string that cannot be parsed) are moved to a quarantine list and excluded from incident counts but included in the final report with a specific error flag.
    *   *Trigger*: Failure of timestamp parsing or validation.
