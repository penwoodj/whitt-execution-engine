### Step 1: Initialize Workspace & Layout Documentation
**Rule:** Create `/tmp/opencode/alert-run/` with subdirectories `raw/`, `processed/`, `logs/`, `scripts/`, and `reports/`. Write `README.md` defining the layout, execution order, and "stranger-proof" reproducibility requirements. Log: `Initialized workspace at /tmp/opencode/alert-run; directories created.`

### Step 2: Ingest Raw Data & Handle Timestamp Dispositions
**Rule:** Read all input files into `raw/`. Parse timestamps (handling mixed formats). For the 8 out-of-order alerts, flag them in a CSV column `timestamp_status` as `QUARANTINED` with reason `OUT_OF_ORDER_SEQ`. Log: `Ingested raw data; identified 8 alerts with out-of-sequence timestamps and marked for quarantine.`

### Step 3: Group Alerts into Incidents (Template + Time Proximity)
**Rule:** Iterate through sorted, valid-alerts. If `alert.template` matches previous group AND `abs(current_ts - last_ts) < 60s`, append to current incident; else start new incident. Store in `processed/incidents.csv`. Log: `Grouped alerts into incidents based on template similarity and 60-second time proximity.`

### Step 4: Count Incidents & Calculate Metrics (Span, Blast Radius)
**Rule:** Compute total incident count. Identify max incident size (`max_incident_span`). Calculate service blast radius per incident (unique services). Output to `processed/metrics.csv`. Log: `Computed incident counts, maximum span, and service blast radii for all incidents.`

### Step 5: Identify Noise Makers (>10 Alerts)
**Rule:** Filter incidents where `incident_count > 10`. List these as "Noise Makers" in `processed/noise_makers.csv` with their template and count. Log: `Identified noise maker incidents (count > 10) for further analysis.`

### Step 6: Severity Normalization Pass
**Rule:** Map severities to standard levels (`critical`, `warning`, `info`). Apply rule: if `severity == 'CRITICAL'` AND `message_template` contains known low-severity keywords OR it is the only alert with that template, downgrade to `warning`. Output normalized data to `processed/normalized_alerts.csv`. Log: `Performed severity normalization; downgraded 1 all-caps CRITICAL typo based on context.`

### Step 7: Generate Rules Documentation
**Rule:** Write `scripts/rules.md` containing the exact logic for grouping (60s window), noise maker threshold (>10), and severity normalization rules. Log: `Generated scripts/rules.md with explicit grouping, noise, and severity rules.`

### Step 8: Create Storm Report & JSON
**Rule:** Generate `reports/storm-report.md` summarizing the storm (total alerts, incidents, noise makers, normalized severities) using tables. Generate `reports/storm.json` containing structured metrics. Log: `Generated reports/storm-report.md and reports/storm.json with summary tables.`

### Step 9: Verification & Conservation Check
**Rule:** Write `scripts/verify.py`. Recompute total alerts from raw files, sum counts in incidents, check that `sum(incident_counts) == total_alerts - quarantined_count`. Assert conservation of data. Log: `Verification passed; conservation check confirmed all non-quarantined alerts accounted for.`

### Step 10: Final Timing Table & Execution
**Rule:** Record start/end timestamps for each stage in a table within the final report. Ensure all scripts run sequentially without external dependencies. Log: `Final timing table generated; pipeline executed successfully with zero external dependencies.`
