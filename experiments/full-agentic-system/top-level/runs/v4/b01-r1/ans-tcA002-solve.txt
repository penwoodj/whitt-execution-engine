### 6. Self-Assessment

**Where this harness would break first:**
This simulation-based harness is robust for logic verification but brittle regarding data integrity assumptions. The primary failure point is the **Unanswerable Question Logic**. If the mutation script inadvertently introduces a resolution timestamp (even if sparse) into the dataset, `solution-hallucinate` might stop failing on Q4 and start passing it with a made-up number that looks "plausible" but is wrong, causing a false positive. The grader relies on strict schema validation; any deviation in data structure (e.g., adding a column not defined in the spec) would break the `compute_answers.py` logic silently or crash it.

The second failure point is **Floating Point Tolerance**. Questions involving percentages (Q2, Q6, Q11) rely on tolerance of +/- 0.01. If the mutation script changes data such that a percentage becomes exactly on the boundary (e.g., 45.005%), minor rounding differences between the grader and the truth file could cause a valid answer to be marked wrong, leading to an incorrect "Fail" verdict for `solution-perfect`.
