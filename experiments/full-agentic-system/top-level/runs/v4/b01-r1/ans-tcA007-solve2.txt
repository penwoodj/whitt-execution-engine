### Phase 1: Rule Scan & Logic Definition

Based on the requirements for an alert storm dedup pipeline handling messy inputs (mixed timestamps, out-of-order alerts, noise makers), here are the rules that define state changes during the event processing.

| Rule ID | Trigger Event Type | State Change Logic |
| :--- | :--- | :--- |
| `R01_GROUP` | Alert Arrival | If `template` matches existing incident AND `time_diff < 5m`, merge into current incident. Else, create new incident. |
| `R02_NOISE` | Alert Arrival | If count(`template`) > 10 within span, flag as "Noise Maker". State: `is_noise = true`. |
| `R03_TIME_FIX` | Timestamp Parse | Detect mixed formats (ISO vs Unix). Normalize all to ISO8601. Reject if unparseable. |
| `R04_ORDER_FIX` | Alert Arrival | If alert timestamp < previous alert timestamp in stream, flag as "Out-of-Order". Sort by normalized time for grouping logic. |
| `R05_SEV_NORM` | Severity Parse | Detect mixed casing (e.g., "CRITICAL" vs "critical"). Normalize to lowercase. Flag if typo exists (e.g., all-caps where others are mixed). |

```markdown
# Alert Storm Dedup Rules

1. **R01_GROUP**: Group alerts by `template` if they occur within 5 minutes of each other.
2. **R02_NOISE**: Flag an incident as a "Noise Maker" if the alert count for its template exceeds 10.
3. **R03_TIME_FIX**: Normalize all timestamps to ISO8601. Reject unparseable entries.
4. **R04_ORDER_FIX**: Sort alerts by normalized timestamp before grouping to handle out-of-order arrivals.
5. **R05_SEV_NORM**: Normalize severity strings to lowercase. Flag "CRITICAL" (all-caps) as a potential typo if mixed with others.
```
