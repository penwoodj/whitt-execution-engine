**Phase 1 RULE SCAN**
1. **Load Rule**: A load command attempts to add a model of specified size; if it fits in remaining free space, the model is added and marked as touched (most recent).
2. **Eviction Rule**: If a load does not fit, the system evicts one unpinned model at a time, specifically choosing the least-recently-touched (LRU) among all *unpinned* models, until enough space exists or only pinned models remain.
3. **Pinning Constraint**: Model C is pinned and can never be evicted.
4. **Defer Rule**: If after exhausting all unpinned models a load still does not fit (because only pinned models remain), the load is deferred; no eviction occurs for this specific load, and its ID is recorded as deferred.
5. **Touch Update Rule**: Every time a model is loaded or accessed during an eviction process, it moves to the most-recent position in the recency list.
6. **Unload Rule**: An unload command frees the specified amount of space; if the model is not resident, this is a no-op.
7. **Count Definitions**: `loads` counts successful additions; `evictions` counts total models removed from residency (summed across all events); `deferrals` counts loads turned away due to lack of space despite emptying unpinned pool; `deferred` lists the IDs of deferred loads in order.
