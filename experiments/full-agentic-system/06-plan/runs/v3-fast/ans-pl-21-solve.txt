### Phase 1 RULE SCAN

The following rules govern the state changes during the event stream:

1.  **Arrival/Load Rule**: Upon request of a model $M$ with size $S$, if current free space $\ge S$, load $M$. State becomes resident, free space decreases by $S$, recency updates to $M$.
2.  **Eviction Trigger Rule**: If current free space $< S$, initiate eviction process targeting the Least-Recently-Touched (LRT) *unpinned* model(s).
3.  **Single Eviction Step Rule**: Identify the single LRT unpinned model. Evict it if its size $\le$ available free space + remaining needed space? No, evict one by one until fit. Specifically: Check if `free_space >= S`. If not, find LRT unpinned $X$. Evict $X$ (add to eviction count). Update state. Repeat check.
4.  **Deferred Load Rule**: If after evicting *all* available unpinned models, free space is still $< S$, mark load as deferred. Record ID in `deferred` list. No further evictions occur for this specific load (even if pinned models exist).
5.  **Recency Update Rule**: Every successful load or eviction of a resident model updates that model's recency to "Most Recent". Unloaded models are removed from the resident set.
6.  **Pinned Model Immunity Rule**: Pinned models (Model B) are never selected for eviction, regardless of recency or size constraints.
7.  **Unload Rule**: Upon request `unload M`, if $M$ is resident, free space increases by size($M$), remove from resident set. If not resident, no-op.

**Trigger Mapping:**
*   Event "load A": Triggers Arrival/Load Rule (fits).
*   Event "load B": Triggers Arrival/Load Rule (fits).
*   Event "load C": Triggers Arrival/Load Rule (fits).
*   Event "load D": Triggers Eviction Trigger Rule -> Single Eviction Step Rule (evicts A) -> Arrival/Load Rule.
*   Event "unload B": Triggers Unload Rule.
