### Phase 1 RULE SCAN
*Listing every rule that changes state during the event or claim list.*

1.  **Arrival Rule**: Requests land in strict arrival order; each asks for a fixed number of tokens.
2.  **Grant Rule (Full)**: If `pool >= ask`, grant full amount, `pool -= ask`.
3.  **Grant Rule (Partial)**: If `0 < pool < ask`, grant partial amount (`pool`), `pool = 0`. Request is still "granted", never denied.
4.  **Denial Rule**: If `pool == 0`, request is denied, listed by ID. Pool remains 0.
5.  **Expiry Trigger Rule**: The grant for `r2` expires after request `r3` completes (triggered by completion of the event immediately following the named trigger).
6.  **Return Calculation Rule**: Expiry returns half of the *granted* amount (`floor(granted / 2)`), rounded down.
7.  **Return Timing Rule**: The return lands right before the request the trigger names (conceptually applied to the state just prior to processing the next arrival, or immediately after the trigger event's completion).
8.  **Pool Update Rule**: `pool += returned_amount`.
