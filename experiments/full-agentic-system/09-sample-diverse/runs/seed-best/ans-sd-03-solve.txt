### Phase 1 RULE SCAN
The following rules govern the state changes during the event list. Each rule is listed on one line with its triggering condition.

1. **Arrival Rule**: A request arrives at the current pool level; if `pool >= ask`, grant full amount and reduce pool by `ask`; if `pool < ask` but `pool > 0`, grant partial amount (`pool`) and reduce pool to `0`.
2. **Denial Rule**: If a request arrives when `pool == 0`, the request is denied, its ID is recorded in the denial list, and the pool remains `0`.
3. **Expiry Trigger Rule**: Upon completion of Request R2 (the second event), any grant associated with Request R1 expires.
4. **Return Calculation Rule**: The expired grant returns `floor(granted_amount / 2)` tokens to the pool immediately before processing the next request (R3).
5. **State Update Rule**: After every action (grant, denial, or return), the pool state is updated and recorded as the new current balance.
