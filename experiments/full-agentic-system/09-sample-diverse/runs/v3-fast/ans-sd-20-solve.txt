### Phase 1 RULE SCAN
The following rules govern the state changes during the event stream:
1. **Arrival/Load Rule**: A load request attempts to occupy `size` GB of free space. If sufficient free space exists, the model is loaded (state change: resident added).
2. **Eviction Trigger Rule**: If a load cannot fit in available free space, the system identifies all unpinned residents sorted by Least-Recently-Touched (LRT) and evicts them one-by-one until enough space exists or only pinned models remain. Each eviction increments the `evictions` counter.
3. **Deferral Rule**: If after exhausting all unpinned residents a load still cannot fit, the load is deferred. The model is not loaded, no further evictions occur for this specific request, and the load ID is recorded in the `deferred` list (state change: deferral recorded).
4. **Touch/Recency Rule**: Upon any successful load or eviction of a resident, that model's recency is updated to "Most-Recently-Touched".
5. **Unload Rule**: An unload request frees the specified model's size if it is currently resident. If not resident, it is a no-op (state change: free space increased).
