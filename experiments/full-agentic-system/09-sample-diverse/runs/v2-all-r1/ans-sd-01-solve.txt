### Phase 1 RULE SCAN
*List of rules changing state during the event or claim list:*

1.  **Arrival Rule**: A request arrives in strict arrival order asking for a fixed number of tokens.
2.  **Grant/Partial/Deny Rule**: If the pool has tokens, grant `min(ask, pool)`. The pool drops by the granted amount. If the pool is exactly zero upon arrival, deny the request (add ID to denied list). A partial grant is still a "granted" state, not denied.
3.  **Expiry Trigger Rule**: Upon completion of request $R_{trigger}$, any grant associated with $R_{trigger}$ expires.
4.  **Return Rule**: The expired grant returns `floor(granted_amount / 2)` to the pool immediately before the next event is processed (or effectively right after the trigger completes).
5.  **State Update Rule**: Pool balance updates sequentially: `Pool = Pool - Grant + Return`.
