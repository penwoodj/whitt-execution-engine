### Phase 1 RULE SCAN
The following rules govern the state changes during the event stream:

1.  **Arrival/Load Rule**: Upon request of a model $M$ with size $S$, if current free space $\ge S$, load $M$. State becomes resident, free space decreases by $S$, recency updates to $M$.
2.  **Eviction Trigger Rule**: If current free space $< S$, initiate eviction sequence targeting **unpinned** models only.
3.  **LRU Selection Rule**: Within the set of unpinned residents, select the model with the oldest touch time (Least Recently Used).
4.  **Single Eviction Step Rule**: Evict exactly one selected LRU unpinned model. Update free space by adding its size. Increment eviction counter. Recency updates to the newly freed slot's position relative to others (effectively moving the evicted model out, shifting indices of remaining models). Repeat until free space $\ge S$ or no unpinned models remain.
5.  **Deferral Rule**: If after exhausting all unpinned models, free space is still $< S$, mark load as deferred. Record ID in `deferred` list. Do not increment eviction counter for this step (no model was removed). State remains unchanged regarding residents.
6.  **Recency Update Rule**: Every time a model is loaded or an existing resident is touched (implicitly handled by the "load" action fitting), it becomes the most recently used. Eviction logic relies on the order of these updates.
7.  **Unload Rule**: Upon request to unload model $M$, if $M$ is resident, free space increases by size($M$). If $M$ is not resident (already evicted or never loaded), this is a no-op.

**Events triggering rules:**
*   `load A`: Triggers Arrival/Load Rule (Rule 1).
*   `load B`: Triggers Arrival/Load Rule (Rule 1) -> Fits immediately.
*   `load C`: Triggers Arrival/Load Rule (Rule 2, 3, 4) -> Requires eviction of unpinned models.
*   `load D`: Triggers Arrival/Load Rule (Rule 2, 3, 4) -> Requires eviction of unpinned models.
*   `unload B`: Triggers Unload Rule (Rule 7).
