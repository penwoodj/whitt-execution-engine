The task requires walking a state machine based on specific rules for source ranking and claim verification, then outputting the result in a strict JSON format.

**Phase 1: Rule Analysis (Mental Check)**
*   **Source Hierarchy:** Machine Log > Signed Handoff > Hallway Hearsay > Dashboard.
*   **Verification Logic:**
    *   If sources agree -> `true`.
    *   If higher source contradicts lower source -> Higher wins (`true`), Lower assertion becomes `false`.
    *   If a claim rests *only* on hearsay or *only* on the dashboard -> `unverified`.
    *   Claims resting on mixed valid sources (even if contradictory) are resolved to `true` or `false`, not `unverified`.

**Phase 2: Event Walk & State Application**

1.  **Claim c1:** "the machine log shows the shard rebalanced at 02:10."
    *   Source: Machine Log (Highest).
    *   Status: Single valid source. No contradiction.
    *   Result: `true`.

2.  **Claim c2:** "a signed handoff says the shard never moved, the machine log shows it moved at 02:10."
    *   Sources involved: Signed Handoff (Lower), Machine Log (Higher).
    *   Logic: Higher source (Machine Log) contradicts Lower source (Signed Handoff).
    *   Resolution: The assertion of the higher source is `true`. The assertion of the lower source counts as `false`.
    *   Result: `true` (The event described by the Machine Log happened).

3.  **Claim c3:** "a signed handoff puts the backup at 03:00, hallway hearsay says 03:00 too."
    *   Sources involved: Signed Handoff (Higher), Hallway Hearsay (Lower).
    *   Logic: Sources agree on the content ("backup at 03:00").
    *   Resolution: Agreement implies `true`.
    *   Result: `true`.

4.  **Claim c4:** "hallway hearsay alone claims the cache was cold at 04:00."
    *   Source: Hallway Hearsay (Lower).
    *   Constraint Check: The rule states "a claim resting only on hearsay... is UNVERIFIED".
    *   Result: `unverified`.

5.  **Claim c5:** "only the buggy dashboard shows the queue depth peaking at 05:00."
    *   Source: Dashboard (Lowest).
    *   Constraint Check: The rule states "...or only on the dashboard, is UNVERIFIED".
    *   Result: `unverified`.

**Final State Compilation:**
*   **true**: [c1, c2, c3]
*   **false**: [] (No claims were explicitly denied by a higher source; they were either verified true or unverified).
*   **unverified**: [c4, c5]

Sorting IDs: All are single letters. Order is c1, c2, c3, c4, c5.

**JSON Output Construction:**
```json
{"true": ["c1", "c2", "c3"], "false": [], "unverified": ["c4", "c5"]}
```
