### Phase 1: Rule Scan

The following rules govern the state changes during this event list. Each line identifies a rule and the specific trigger that activates it in strict chronological order.

1.  **Arrival Trigger**: `HIGH` arrives at minute 5, triggering an immediate preemption of any running `LOW` job (if applicable).
2.  **Checkpoint Banking Rule**: Any `LOW` job starting or resuming banks a checkpoint at $T_{start} + 2$ and every subsequent absolute minute divisible by 2 relative to its start time ($T_{bank} = T_{start} + 2k$). This rule activates upon the event "Start" or "Resume".
3.  **Waste Calculation Rule**: Upon preemption, minutes elapsed since the last valid checkpoint bank are calculated as wasted work ($Waste = CurrentMinute - LastBankMinute$). This rule activates on the event "Preempt".
4.  **Resumption Priority Rule**: If multiple `LOW` jobs are waiting after a minute finishes or is preempted, the job with the lower start minute (or previously resumed status at a tie) is selected to run next. This rule activates on the event "Select Next Job".
5.  **Completion Trigger**: A `LOW` job finishes when its remaining duration reaches zero at the end of an occupied minute. This rule activates on the event "Finish".
6.  **Makespan Aggregation Rule**: The global maximum finish minute is updated whenever a job completes. This rule activates continuously on every "Finish" event.
