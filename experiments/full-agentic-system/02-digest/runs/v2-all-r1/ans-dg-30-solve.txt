### Phase 1: Rule List
The following rules govern the state changes during the event list (arrivals, grants, preemptions, expiries/returns):

1.  **Arrival & Granting**: A job arriving at minute $s$ with duration $d$ claims the core starting at minute $s$. It banks a checkpoint immediately if $s + 2 < s+d$ is not yet reached (specifically at absolute minute $s+2$).
2.  **Checkpoint Banking Rule**: Checkpoints are banked at absolute minutes $start+2$, $start+4$, etc., relative to the job's start or resume time. A bank landing exactly on the HIGH arrival minute counts as valid; no work is wasted up to that point.
3.  **Preemption & Expiry (Waste) Rule**: When HIGH preempts a running LOW at absolute minute $T$:
    *   Determine the last banked checkpoint $\le T$.
    *   Calculate waste: Minutes past the last bank are wasted ($T - \text{last\_bank}$).
    *   The job resumes later with "owed" = Total Duration - Banked Duration.
4.  **Resume & Ranking Rule**: Upon resume, the LOW continues execution. If multiple LOWs wait, the one with the earlier start minute ranks higher. If start minutes tie, a resumed (non-zero owed) job outranks a fresh (zero owed) job.
5.  **Completion Order Rule**: The output list contains ONLY LOW jobs, sorted by their absolute finish minute. HIGH is excluded from this specific order list but contributes to the makespan clock.
