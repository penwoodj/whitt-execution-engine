### Phase 1 RULE SCAN

Based on the task description, here are the rules that change state during the event or claim list:

1.  **Arrival Rule**: Requests land in strict arrival order; each asks for a fixed number of tokens.
2.  **Grant Rule (Full)**: If the pool covers the full ask, grant the full amount and subtract from the pool.
3.  **Grant Rule (Partial)**: If the pool cannot cover the full ask, grant what is there (the remaining pool) and set the pool to zero.
4.  **Denial Rule**: A request arriving at an empty pool is denied and listed by id; no tokens are granted or returned for this specific event's grant logic.
5.  **Expiry Trigger Rule**: The grant for `r2` expires after request `r3` completes (triggered by the completion of `r3`).
6.  **Return Calculation Rule**: An expired grant returns half its granted tokens, rounded down (`floor(granted / 2)`).
7.  **Timing Rule**: The return lands right before the request the trigger names (`r4`), not after it.
