### Phase 1 RULE SCAN
The following rules govern the state changes during the event stream:

1.  **Arrival/Load Rule**: Upon request of a model $M$ with size $S$, if current free space $\ge S$, load $M$. If $M$ is pinned, it stays resident forever; otherwise, it becomes unpinned and moves to most-recent position.
2.  **Eviction Rule (Fit Check)**: If current free space $< S$, identify all unpinned models sorted by recency (oldest first). Evict the oldest unpinned model one at a time until either:
    *   Free space $\ge S$ (Load succeeds), OR
    *   No unpinned models remain.
3.  **Deferral Rule**: If free space $< S$ and only pinned models remain, do not evict any models. Record the request as a deferral with the requested model ID in the deferred list.
4.  **Recency Update Rule**: Every time a model is loaded (successfully or via eviction) or touched (implicitly handled by load), it moves to the most-recent position. Evicted models are removed from recency tracking.
5.  **Unload Rule**: Upon request to unload $M$, if $M$ is resident, free its size and move it to most-recent (if unpinned). If $M$ is not resident, this is a no-op.

**Trigger Mapping:**
*   Event `load A` triggers Rules 1 & 4.
*   Event `load C` triggers Rules 1 & 4.
*   Event `load D` triggers Rules 2, 3 (conditional), or 4.
*   Event `unload D` triggers Rule 5.
