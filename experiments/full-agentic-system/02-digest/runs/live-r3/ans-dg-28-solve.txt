### Phase 1 RULE SCAN
This phase lists every rule in the task that changes state during the event or claim list (tonight's events), one line each, marking which event triggers it.

1. **Arrival Rule**: `HIGH` arrives at minute 3 and runs for 6 minutes; this event triggers the preemption of any running `LOW` job and blocks all other execution until `HIGH` completes.
2. **Preemption Rule**: When `HIGH` starts (minute 3), it instantly preempts whatever `LOW` job is running, causing that job to pause immediately at minute 3.
3. **Checkpoint Rule**: `LOW` jobs checkpoint every 2 completed minutes of running time; this rule applies continuously as `LOW` jobs run, saving state at the end of their 2nd and 4th minutes (if they reach them).
4. **Waste Rule**: On preemption, work past the last checkpoint is wasted and redone after resume; this rule applies when a preempted `LOW` job resumes, calculating the difference between its current running time and its last saved checkpoint.
5. **Scheduling Order Rule**: `LOW` jobs take the core in order of their start minutes (0 then 3); this rule determines which waiting `LOW` starts next after a gap or preemption.
6. **Tie-Breaker Rule**: A resumed `LOW` outranks a fresh one at any tie; this rule applies if two `LOW` jobs become available simultaneously, prioritizing the one that was preempted over the one just started.
7. **Makespan Calculation Rule**: Makespan counts from the first start of any job (minute 0) to the last finish of any job; this rule aggregates the timeline for the final output.
8. **Completion Order Rule**: Completion order lists `LOW` jobs by the minute each finishes; this rule sorts the final results based on finish times.
