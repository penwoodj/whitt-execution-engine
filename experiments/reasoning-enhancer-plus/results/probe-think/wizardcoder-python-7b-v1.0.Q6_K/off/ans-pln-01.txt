3. If any issues are found, fix them and redeploy to staging.
4. Promote the new version to production if all tests pass.
5. Monitor the application's error rate over a period of time (e.g., 24 hours).
6. If the error rate exceeds 2%, rollback to previous version and revert to canary phase at 10% traffic.
7. Repeat steps 3-5 until error rate is below 2%.
8. Deploy the new version to production with full traffic.
