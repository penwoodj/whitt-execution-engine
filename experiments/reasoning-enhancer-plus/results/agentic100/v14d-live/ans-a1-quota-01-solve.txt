### Step 1: Understand the rules

We have a system with:

- **Base capacity**: Each team starts with **100 TB** base. This never rolls over.
- **Flagged unused banks**: Teams can flag unused portions of their bank (i.e., unused TB) to be moved into the overflow pool for next month.
  - Flagged amount is **moved exactly to the next month**, and expires if not used in that month.
- **Overflow pool**:
  - Holds up to **50 TB** total.
  - Grants one-shot requests strictly in arrival order (FIFO), full grants, no splitting.
  - Only grants when requested; if overflow is empty, no more grants.
  - Denials cost nothing and touch nothing — just record the denial.
- **Banks are per-team**, so no transfers between teams.
- The **pool's remainder** is what remains after fulfilling requests from the queue.

---

### Step 2: Last month’s usage and flagging

We are told:

- **Atlas**: used 70 TB → unused = 100 - 70 = 30 TB → flagged 20 of its unused
- **Borealis**: used 100 TB → unused = 0 → flagged 0
- **Cascade**: used 40 TB → unused = 60 TB → flagged 45 of its unused

So, the amount **flagged** (i.e., moved to overflow pool) is:

- Atlas: 20 TB
- Borealis: 0 TB
- Cascade: 45 TB  
→ Total flagged = 20 + 0 + 65 = 65 TB

But the **overflow pool only holds 50 TB**.

So, only **up to 50 TB** can be added to the pool. The excess is not stored — it's lost or discarded?

Wait: rule says "flagged unused banks into exactly next month then expires if unused"

→ So flagged amounts are moved to the overflow pool for next month.

But the overflow pool has a **maximum of 50 TB**.

So, only up to 50 TB can be stored in the pool. Any amount over 50 TB is not stored — it's lost?

Yes: "overflow pool holds 50 TB" → implies capacity limit.

Therefore:

- Total flagged = 20 (Atlas) + 0 (Borealis) + 45 (Cascade) = **65 TB**
- Pool can only hold **50 TB** → so only **50 TB** is stored in the pool
- The remaining **15 TB** of flagged unused banks are **not stored**, and thus expire or go unused — they do not become available for next month.
