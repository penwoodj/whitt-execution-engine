Let's go step by step through every rule and compute the required values.

---

**Step 1: Understand the setup**

We have a system with an 8 GB residency cap. This means that at any time, the total memory used (i.e., model size) must not exceed 8 GB.

Jobs run in strict order:
- Job A: needs 3 GB model
- Job B: needs 5 GB model
- Job C: needs 5 GB model

Only the "m2" model begins loaded. This means at the start, the system has a 3 GB model (since m2 is 3 GB) already loaded.

Each job must have its model resident *at the start* of execution. After each job finishes, the model is unloaded for maintenance.

- Load cost: 30 seconds per load
- Unload cost: 10 seconds per unload

We are to compute:
- Total number of loads (loads)
- Total load time in seconds (load_s)
- Total unload time in seconds (unload_s)

Note: The scanner doesn't manage timestamps, and we don’t need to track intermediate states — just total values.

---

**Step 2: Track job execution order**

Jobs run in order: A → B → C

We start with the m2 model already loaded. So at start:
- Model is loaded (3 GB), no load operation needed yet.

Now, process each job:

---

**Job A: needs 3 GB model**

- Already has a 3 GB model loaded → no need to load
- So, **no load** for Job A
- After Job A finishes, the model must be unloaded → **1 unload** (10 seconds)

→ Load count: 0  
→ Unload count: 1

---

**Job B: needs 5 GB model**

- Current model is 3 GB. We need a 5 GB model.
- So we must load a new 5 GB model
- This is the first time we are loading a new model → **1 load**
- Load takes 30 seconds → add to load_s
- After Job B finishes, unload the model (now that it's done) → **1 unload** (10 seconds)

→ Load count:  0 + 1 = 1  
→ Unload count: 1 + 1 = 2

---

**Job C: needs 5 GB model**

- Current model is 5 GB (from Job B). We need a 5 GB model.
- But we already have one? Do we need to load again?

Important rule: "each job's model must be resident at start"

So for Job C, we must have the required model loaded *before* it starts.

Currently, after Job B finishes, the 5 GB model is unloaded (as per maintenance). So at the start of Job C, no model is loaded
