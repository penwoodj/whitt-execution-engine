Let's go step by step through every rule and fact provided:

---

**Step 1: Understand the rules**

- Server dedupes by request ID: This means if the same request ID appears multiple times, it is counted only once (charged once per unique request ID).
- Refunds are out of scope → we don't need to consider refunds.
- Console rendering duplicate line items is a display issue, not ledger impact → duplicates shown in UI do not affect actual ledger entries. So, only real transactions matter.
- We are to compute:
  - Total charged: the total amount actually charged to the customer (based on unique request IDs).
  - Deduped: how many submissions were absorbed by deduplication (i.e., how many duplicate requests were removed).

---

**Step 2: Extract facts from prompt**

- Request K (carrying $75) was submitted **twice**.
- Request M ($30, different cart) went through once.
- Requests are unrelated → so request K and M are distinct in terms of ID and content.

→ Since deduplication is by request ID:
  - If the same request ID appears twice, only one charge occurs.
  - Different IDs (like K vs. M) are treated separately.

---

**Step 3: Apply rules to facts**

- Request K was submitted twice → but deduped by request ID → so only **one** charge for request K ($75).
- Request M was submitted once → one charge of $30.
- No refunds involved (out of scope).

→ Total charged = $75 + $30 = $105

Now, how many submissions were absorbed by deduplication?

- Request K was submitted twice → one duplicate → so **one** submission was absorbed (deduplicated).
- Request M: only once → no duplication → 0 duplicates.
- So total deduped submissions = 1.
