# 03 — Workflow Design (fusion-v1)

## Shape

One workflow YAML, two modes (spoof/live), generated by
`gen-fusion-workflow.py`. Per-case step chains wired by GWT gates on
quoted tokens. Stage-major step order (native v7 lesson: kills swap
ping-pong, driver parity).

### H chain (13 steps)
```
plan(think,1000,UNCHECKED) → solve(fmt,600) → extract(fmt,200)
→ replan(fmt,250,UNCHECKED,prior=plan+solve+failures) → solve2(fmt,600)
→ extract2(fmt,200) → wait(fmt,400) → extract3(fmt,200)
→ sample2(deep,1500) → extract4(fmt,200) → verify(think,3500)
→ extract5(fmt,200) → judge(think,300,UNCHECKED blind lane) → terminal
```

### L chain (4 steps)
```
solve(fmt,400) → extract(fmt,200) → judge(think,300) → terminal
```

Checked stages H: solve,extract,solve2,extract2,wait,extract3,
sample2,extract4,verify,extract5 (10). L: solve,extract (2).
UNCHECKED (no deterministic check — scaffold lanes): plan, replan,
judge. Judge never gates anything; it only writes judge.json for the
collector's two-lane record (N5).

## Stage semantics

| stage | style prefix | prior context | notes |
|---|---|---|---|
| plan | "PLAN FIRST: list steps..." | digest core | ordering scaffold only (P4) |
| solve/solve2/sample2 | "Think step by step through every rule, then answer." (P1 byte-exact) | solve2: replan+solve; sample2: none (fresh) | unconstrained reasoning (N2) |
| extract* | harvester prompt | immediately-prior attempt TAIL 4000 | check-before-echo; CLEANED_JSON path |
| replan | "RE-PLAN: prior plan invalidated by failed checks..." | plan + solve + failure list | N4 invalidation gate |
| wait | "Wait. Prior attempt near-miss..." | solve2 | E1 bounded, last cheap rung |
| verify | "BACKWARD CHECK: test each stated rule..." | extract4 prior sample | E9 expensive-last |
| judge | blind: answer text + rubric question only | final winning answer | cross-role lane, logged |

## Gate mechanics (unchanged from proven REA+ machinery)

- `before_step_starts`: shell gate (fusion-spoof-emit or
  fusion-stage-emit) prints quoted token; GWT `== "PASS"` routes next
  case-stage, `== "SKIP"` routes onward in chain.
- skip-if-won: any passing check for the case short-circuits all its
  later stages (zero-call termination, P6).
- `after_step_succeeds`: save_to `$text_state` + absolute path under
  run-dir; live mode: check-answer.py writes check json; log hook
  event_fields step_name/model_name/duration_ms/token_count.
- terminal step: `skip_step: true`.
- timing: cooldown 0, min_tmp_space_mb 50.

## Models (roles, P9)

fmt = Qwen3-4B-Instruct-2507-Q4_K_M · deep = Bonsai-27B-Q1_0 ·
think = Qwen3-4B-Thinking-2507-Q4_K_M. Single-model-resident windows
in stage-major order; safe-launch discipline applies to live phase.

## Spoof scenario design

Win-depth over checked stages, deterministic sha256(cid) hash:
H: 30% win 0 (solve), 40% win mid (extract2..sample2 band), 30% win
deep (verify band). L: 80% win 0, 20% win 1. Judge lane: 10% hash →
judge "fail" while det pass (exercises det-overrides-judge two-lane
path in the collector). Unchecked stages emit scaffold artifacts +
SKIP token (never PASS — they cannot win a case).

## conf pre-gate (N3, live-phase hook)

`fusion-conf.py`: entropy over first-token logprobs from the chat
completion endpoint; entropy < 0.8 → LIGHT (L-chain), ≥ 0.8 → HEAVY.
Wire point: pre-classify shell hook before case metadata overrides.
Not wired into YAML this phase — requires live server logprobs; unit
tested against fixture files; wiring spec in 04.

## Digest contract (E10/P8)

Slice at `and to say the rules one more time` (expansion start) +
re-attach from `before committing, recheck each number` (spec tail).
Target ≤ 220 words to model. Numbers/traps preserved verbatim (digits
stay digits — [S27]).
