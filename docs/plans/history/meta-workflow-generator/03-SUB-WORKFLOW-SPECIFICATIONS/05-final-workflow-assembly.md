# SW5 Specification — Final Workflow Assembly

| Attribute | Value |
|-----------|-------|
| Workflow ID | `sw5_final_workflow_assembly` |
| YAML file | `docs/benchmarks/workflows/sw5-final-workflow-assembly.yml` |
| Output | `docs/benchmarks/outputs/meta-workflow/<RUN_ID>/sw5/workflow.yml` (executable YAML) |
| Reads from | `sw4/structs.md` (+ `sw1/tasks.md` for exhaustive cross-check) |
| Consumed by | End user — the final deliverable of the meta-workflow |
| Model | `qwen35` only |
| Iteration target | Per-task exhaustive verification loop (CRITICAL) |

---

## 1. Purpose

Selectively assemble a complete, valid, executable agentic workflow YAML file from
the substructures documented in `structs.md`. **This is the most important step**:
every task in `tasks.md` MUST appear in the final workflow AND be exhaustively
handled (its desired end-state from `outputs.md` must be achievable by the YAML).

## 2. Output Schema (`workflow.yml`)

A complete whitt unified-workflow-schema YAML:

```yaml
workflow_id: generated-workflow-<run-id>
name: "Generated Workflow"
description: "Auto-generated by meta-workflow-v6"
version: "1.0.0"
schema_version: "2.0.0"
min_schema_version: "2.0.0"

providers:
  llama_cpp_with_vulkan:
    config:
      host: localhost
      port: 8080

models:
  "qwen35":
    name: "Qwen3.5-9B-UD-Q4_K_XL.gguf"
    host:
      type: llama_cpp_with_vulkan

workflow_execution_strategy:
  memory:
    model_lifecycle:
      unload_unused: true

agentic_workflow:
  when:
    after_workflow:
      - log:
          to_file_path: "./docs/benchmarks/outputs/logs/workflow.log"
          event_fields: [workflow_id, total_steps, succeeded, failed]
          level: info

  steps:
    step_01_<name>:
      ...
    step_02_<name>:
      ...
    # ... all assembled steps
```

## 3. Pipeline Stages

| Step | Purpose |
|------|---------|
| `step_00_bootstrap` | mkdir sw5/, cat structs.md + tasks.md |
| `step_01_assemble` | LLM: emit full workflow YAML combining all substructures |
| `step_02_post_process` | Shell: `scripts/fix-generated-yaml.py` + `scripts/validate-yaml.py` |
| `step_03_per_task_verify` | LLM (iterate_values over tasks): for each task, verify it's exhaustively handled |
| `step_04_evaluate` | GWT gate on per-task verification |
| `step_05_fix` | LLM: address missing/under-implemented tasks |
| `step_99_finalize` | Save final workflow.yml + bookmark |

## 4. Detailed Step Specifications

### step_01_assemble

```yaml
step_01_assemble:
  generative_entity: "${models.qwen35}"
  depends_on: [step_00_bootstrap]
  prompt: |
    You are assembling a complete whitt workflow YAML.

    SUBSTRUCTURES (each is a YAML block to combine):
    {{bookmarks.sw4_structs.stdout}}

    TASKS (for cross-check during assembly):
    {{bookmarks.sw1_tasks.stdout}}

    OUTPUT a complete YAML file with this exact header (verbatim):

    workflow_id: generated-workflow-__RUN_ID__
    name: "Generated Workflow"
    description: "Auto-generated by meta-workflow-v6"
    version: "1.0.0"
    schema_version: "2.0.0"
    min_schema_version: "2.0.0"

    providers:
      llama_cpp_with_vulkan:
        config:
          host: localhost
          port: 8080

    models:
      "qwen35":
        name: "Qwen3.5-9B-UD-Q4_K_XL.gguf"
        host:
          type: llama_cpp_with_vulkan

    workflow_execution_strategy:
      memory:
        model_lifecycle:
          unload_unused: true

    agentic_workflow:
      when:
        after_workflow:
          - log:
              to_file_path: "./docs/benchmarks/outputs/logs/workflow.log"
              event_fields: [workflow_id, total_steps, succeeded, failed]
              level: info

      steps:

    For each substructure in SUBSTRUCTURES, copy its YAML content (between ```yaml fences)
    into the steps: section, renaming step names to step_01_<name>, step_02_<name>, etc.
    in dependency order.

    HARD RULES:
    1. First step in steps: has NO depends_on (or depends_on: [])
    2. Every subsequent step depends_on the prior step
    3. Every step has after_step_succeeds with save_to AND log
    4. Every step has after_step_fails with log
    5. ABSOLUTELY NO markdown fences in output (no ```)
    6. File starts with "workflow_id:" on line 1
    7. All file paths use ./docs/benchmarks/outputs/output/ or ./docs/benchmarks/outputs/logs/
    8. Every task from TASKS must have a corresponding step

    Output ONLY raw YAML. First line MUST be "workflow_id:".
  model_overrides: { temperature: 0.05, max_tokens: 8000 }
  when:
    after_step_succeeds:
      - save_to:
          - sw5_assembled
          - "./docs/benchmarks/outputs/meta-workflow/__RUN_ID__/sw5/01-assembled.yml"
      - log:
          to_file_path: "./docs/benchmarks/outputs/meta-workflow/__RUN_ID__/logs/sw5.log"
          event_fields: [step_name, duration_ms, total_tokens]
          level: info
```

### step_03_per_task_verify (CRITICAL — exhaustive check)

```yaml
step_03_per_task_verify:
  generative_entity: "${models.qwen35}"
  depends_on: [step_02_post_process]
  prompt: |
    You are auditing the generated workflow YAML for completeness against the task list.

    TASK TO VERIFY ({{loop.task_id}}):
    {{loop.current_task_action}}

    FULL TASK LIST (for context):
    {{bookmarks.sw1_tasks.stdout}}

    GENERATED WORKFLOW YAML:
    {{bookmarks.sw5_workflow_text.stdout}}

    For THIS specific task ({{loop.task_id}}), output:

    TASK: {{loop.task_id}}
    STEP_NAME_IN_WORKFLOW: <find the step that implements this task, or "MISSING">
    EXHAUSTIVE_COVERAGE: YES | NO
    REASON: <if NO, explain what's missing or under-implemented>
    DESIRED_STATE_MET: YES | NO | PARTIAL
    REASON: <if NO or PARTIAL, what desired-state criterion isn't achievable>

    Rules:
    - "EXHAUSTIVE_COVERAGE: YES" only if the step's prompt + hooks fully implement the task
    - "DESIRED_STATE_MET: YES" only if all testable criteria from outputs.md are achievable
    - Be strict; do not give YES if any doubt

    Output ONLY the audit block.
  model_overrides: { temperature: 0.1, max_tokens: 800 }
  when:
    before_step_starts:
      - iterate_values:
          task_id: ["T1", "T2", "T3", "T4", "T5", "T6", "T7", "T8", "T9", "T10", "T11", "T12"]
          current_task_action: ["T1-action", "T2-action", "T3-action", "T4-action", "T5-action", "T6-action", "T7-action", "T8-action", "T9-action", "T10-action", "T11-action", "T12-action"]
          # NOTE: current_task_action values are placeholders; LLM uses {{loop.task_id}} to
          # look up the action from {{bookmarks.sw1_tasks.stdout}}.
      - shell:
          command: "cat ./docs/benchmarks/outputs/meta-workflow/__RUN_ID__/sw5/02-fixed.yml"
          args: []
          working_dir: "/home/jon/code/whitt-execution-engine"
          fail_on_error: false
    after_step_succeeds:
      - append_to:
          - "./docs/benchmarks/outputs/meta-workflow/__RUN_ID__/sw5/03-task-audit.md"
          - sw5_audit_accumulator
```

### step_04_evaluate

```yaml
step_04_evaluate:
  generative_entity: "${models.qwen35}"
  depends_on: [step_03_per_task_verify]
  prompt: |
    You are the final QA gate for workflow assembly.

    TASK AUDIT RESULTS:
    {{bookmarks.sw5_audit_accumulator.stdout}}

    VALIDATION RESULT (from validate-yaml.py):
    {{bookmarks.shell_output.stdout}}

    Evaluate:
    1. YAML_VALID: validate-yaml.py output contains "VALID:"
    2. ALL_TASKS_PRESENT: Every task from tasks.md has STEP_NAME_IN_WORKFLOW != "MISSING"
    3. ALL_EXHAUSTIVE: Every task has EXHAUSTIVE_COVERAGE: YES
    4. ALL_DESIRED_MET: Every task has DESIRED_STATE_MET: YES
    5. NO_ORPHAN_STEPS: Every step in YAML corresponds to a task (no extras)

    End with: VERDICT: PASS or VERDICT: FAIL
  model_overrides: { temperature: 0.1, max_tokens: 1200 }
  when:
    after_step_succeeds:
      - save_to:
          - sw5_eval
          - "./docs/benchmarks/outputs/meta-workflow/__RUN_ID__/sw5/04-eval.txt"
      - gwt:
          - given: "{{step.step_04_evaluate.output}} contains 'VERDICT: PASS'"
            then: { route_to: step_99_finalize }
          - given: "true"
            then: { route_to: step_05_fix }
```

## 5. Quality Gates

| Gate | Criterion |
|------|-----------|
| G1 | YAML_VALID: validate-yaml.py reports VALID |
| G2 | ALL_TASKS_PRESENT: no MISSING in audit |
| G3 | ALL_EXHAUSTIVE: every task EXHAUSTIVE_COVERAGE: YES |
| G4 | ALL_DESIRED_MET: every task DESIRED_STATE_MET: YES |
| G5 | NO_ORPHAN_STEPS: every step maps to a task |

## 6. Acceptance Criteria

- [ ] `workflow.yml` is valid per `scripts/validate-yaml.py`
- [ ] `workflow.yml` is executable via `whitt benchmark --workflow workflow.yml`
- [ ] Every task in `tasks.md` has a corresponding step in `workflow.yml`
- [ ] Every desired-state criterion in `outputs.md` is achievable by `workflow.yml`
- [ ] All 5 gates pass
- [ ] Live run completes within 60 minutes
- [ ] Final output **surpasses** Sisyphus manual baseline on at least 3 of 5 prompts
- [ ] Output workflow runs end-to-end on Docker llama.cpp when invoked standalone

## 7. Failure Modes

| Failure | Mitigation |
|---------|------------|
| LLM emits YAML with markdown fences | `scripts/fix-generated-yaml.py` strips |
| YAML parse error | Post-process + validate gate; route to fix |
| Task missing from workflow | per_task_verify catches; fix step adds |
| LLM hallucinates extra steps | NO_ORPHAN_STEPS gate catches |
| Fix loop diverges | Hard cap 5 cycles; advance with WARN |
| Workflow executes but produces wrong outputs | Out of scope for v6 — engine runtime is user concern |
