## Methodology

- **Both systems use identical model:** Qwen3-5-9B-Q4_K_M loaded in `whitt-llama-server` Docker container (llama.cpp + Vulkan)
- **opencode baseline:** Single-shot completion via `scripts/meta-v6/opencode-baseline.sh` (curls llama.cpp `/v1/chat/completions`)
- **SW1-SW5 pipeline:** Full LLM cascade (SW1 task deconstruction → SW2 desired output → SW3 categorization → SW4 YAML emission → SW5 deterministic assembly → workflow execution)
- **Scoring (per prompt):** Size +1 winner, Substantive >500B +2, Refusals -3 each, ≥0.8x size +1

## Analysis

### Where SW1-SW5 wins
- **Code-focused prompts (P12, P13, P14):** SW1-SW5 produces more complete implementations because the multi-step pipeline decomposes the task and assembles coherent code. Single-shot Qwen often truncates or refuses.
- **Prompts requiring decomposition (P09):** SW1-SW5 breaks down into 5+ subtasks and produces substantive output per task. Single-shot produced only 887 bytes — clearly insufficient.
- **P14 refusals:** opencode baseline emitted 5 "I cannot / as an AI / unable to" patterns. SW1-SW5 had 0 refusals because subtask prompts are narrower and less likely to trigger refusal heuristics.

### Where baseline wins
- **Prose-heavy prompts (P06, P07):** Baseline produces larger output (33KB vs 17KB). Single-shot Qwen3.5-9B is verbose in single response. SW1-SW5 synthesis step may truncate due to context budget.
- **P10 documentation extraction:** Baseline produced 10KB vs SW 4KB. The prompt asked for deep document analysis — single-shot had full context window to scan all 12KB of source.

### Honest limitations

1. **SW1-SW5 outputs are from PRE-SW5-refactor runs.** Current SW5 deterministic refactor should produce equal-or-better output. Re-running would solidify the claim.
2. **Baseline lacks tools.** opencode-with-tools would likely score higher. This comparison is "SW1-SW5 (with shell hooks for file access)" vs "Qwen single-shot (no tools)". User's actual goal is to surpass "opencode WITH tools" — that's a future comparison.
3. **Scoring is size-weighted.** A larger deliverable isn't always better. Quality assessment (manual review) would strengthen the claim.
4. **P10 SW deliverable is small (4KB).** Likely because pre-refactor SW5 had assembly issues. Re-run with new deterministic SW5 needed.
