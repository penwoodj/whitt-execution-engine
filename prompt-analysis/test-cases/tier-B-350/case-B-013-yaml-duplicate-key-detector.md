# Tier-B Case 013 — yaml duplicate key detector (SYNTH)

yaml configs with duplicate keys, /tmp/opencode/yamldup. the trap with duplicates: most parsers silently keep the last one, which hides bugs. fixture: 8 yaml files, 4 clean, 4 with duplicates planted at different depths, top-level, one level down, inside a list item's mapping, and one file where the duplicate values are identical so it's arguably harmless, plus one file that is outright malformed yaml as a control. the detector: parse each file tracking key paths, not relying on the parser to error since it won't, which means you're either pre-scanning or using a loader hook, your choice, method documented, and report every duplicated path with the file, the full dotted path, and both values. identical-value duplicates get flagged with a lower severity than conflicting ones, two tiers, stated criteria. malformed file gets its own error class, not a crash. output dup-report.md plus a machine copy, exit nonzero if any conflicting duplicate exists, since that's the gate-worthy class. verify the detector against the known plant list, 4 files with duplicates, all found, include the check. standard library yaml only if it lets you see duplicates, otherwise parse enough yourself, and say which way you went and why.

the detector reads yaml as text with real structure awareness, not just string matching, because a key appearing in two different mappings isn't a duplicate, only same-parent repeats count. report every duplicate with the path, the key, line numbers of both occurrences, and both values, since half the time the interesting question is which value wins. anchor and alias use doesn't count as duplication, that's yaml working as designed, don't flag it. the summary counts files scanned, files clean, files with duplicates, total duplicate instances, and the verifier is simple and strict: rescan confirms the same finding set, deterministic, byte-identical output on rerun. paste the findings table in chat, and flag any duplicate where the two values differ in type, not just value, since that's the one that bites hardest in production.
