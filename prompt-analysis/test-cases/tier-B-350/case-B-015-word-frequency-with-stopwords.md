# Tier-B Case 015 — word frequency with stopwords (LIGHT)

a text stats job, /tmp/opencode/wordfreq. fixture: three plain text articles you write, 500-800 words each, different topics but sharing a handful of theme words, with punctuation, some caps variance, hyphenated words, and numbers scattered in. the counter: tokenize with a stated rule, lowercase, strip punctuation, keep hyphenated words whole, numbers excluded, stopword list of ~40 common english words stated in the output so it's auditable. deliverables: per-article top 25 frequency table, the shared-theme-words analysis, which words are top-10 in all three articles versus distinctive to one, and a type-token ratio per article as a rough richness measure. one wrinkle to handle: the articles use different dash conventions, spaced en-dash versus hyphen, normalize before tokenizing or count them separately, pick and state. output freq.md with tables and a two-sentence honest note on what the frequencies do and don't tell you. standard library only, and paste the shared top-10 list in chat at the end.

tokenization rules stated up front: lowercase before counting, apostrophes stay inside words, hyphens split, digits count as words, and the stopword list is a visible file i can edit, not a buried constant, because stopword choice is an argument, not a fact. run the count twice, once raw and once stopped, and report both top-20 lists side by side, since the difference between them is itself a finding about the corpus. hapax legomena, words appearing exactly once, get a total count and a few examples, because a corpus's rare tail says things its headliners don't. paste the two lists in chat and one line on what the stopped list reveals that the raw one buries. and one honesty note, the top-20 lists are sensitive to the tokenization calls above, so any finding you headline should survive a tweak to them, check that it does. one more: report total tokens and unique types up front, since the type-token ratio frames every list below it.
