# Tier-B Case 003 — json config linter (SYNTH)

build me a small config linter for a specific json schema, workspace /tmp/opencode/configlint. you write the fixture set too: a schema.json describing a config with required keys, typed fields, an enum for one field, and then six config files of which exactly three should pass clean and three should each fail for a different reason, missing required key, wrong type, enum violation. the linter reads the schema, validates each config, and writes a results report, file, verdict, and for failures the exact path of the offending key and which rule broke, not just "invalid". i want the error messages precise enough that someone could fix the config without opening the schema. also a summary line with pass and fail counts that had better be three and three, and the script exits nonzero if any file fails, which is the point of a linter. edge case to handle: one config file is malformed json entirely, that gets its own distinct error class, not a crash and not a schema failure. everything deterministic, no network, standard library. when it runs, paste the full linter output in chat, and include a one-paragraph note on what you'd add to the linter if the schema grew ten more rule types, i'm curious but i'm not asking you to build it.

on strictness: the linter fails closed, anything it can't classify is an error, not a warning, because configs that half-parse are worse than configs that don't. duplicate keys at the same level, last-wins is what parsers do, but i want it flagged loudly with both values shown, since silent last-wins is how a config slowly lies. and the report ends with a one-line verdict per file, clean, warnings only, or errors, so a skim of ten files takes ten seconds. paste the verdict lines in chat when done, plus the count of planted defects found versus planted, since i'm telling you they're in there.
