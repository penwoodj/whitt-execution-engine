# Tier-B Case 006 — markdown table repair (LIGHT)

got a markdown file with broken tables at /tmp/opencode/tablerepair, you create it, one doc with three tables in different states of ruin: one with misaligned pipes but correct rows, one with a row that has too few columns, and one where the header separator row is missing entirely so it renders as plain text. write a repair script that parses each table leniently, normalizes every table to proper aligned markdown with a correct header separator, pads or flags short rows instead of silently truncating them, and inserts the separator where missing, assuming the first row was always meant to be the header, state that assumption in the output. repaired.md is the deliverable plus a changes log listing every repair with table number and what was done. the flag rule for short rows: pad with empty cells but mark the row in the changes log, never guess data. verify by re-parsing the repaired doc, it must parse as three clean tables with consistent column counts, and include that verification result. keep the original file untouched, work on a copy. no deps beyond standard library, nothing interactive, and paste the changes log in chat at the end.

and repair means conservative: fix the structure, never the content, a cell says what it says even if it looks wrong, you flag weird cells in the report instead of editing values. the repaired table must parse clean under a strict column-count check, every row same width, header separated properly, that check is the verifier and it runs on the output. keep an original copy untouched, the whole thing works on a copy so nothing destructive can happen even in theory. paste the before and after row counts plus the defect list in chat, and if a table is too far gone to save, say so and quarantine it instead of mangling it worse.
